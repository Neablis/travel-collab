# F-G01 — A non-UUID path segment reaches Postgres, and every `[tripId]`/`[pageId]`/`[inviteId]`/`[shareId]`/`[savedDayId]` route 500s instead of 404; the board renders the literal text "Internal Server Error"

- **Stream:** G Broken functionality · **Severity:** LOW-MEDIUM (correctness: input handling on every id-bearing route; not a data or security hole) · **Confidence:** CONFIRMED (measured live against a production build by the finder and again by the independent verifier)
- **Area:** `apps/web/src/server/access/trip-access.ts:87-95` → `apps/web/src/server/projections.ts:62` (`eq(tripDetails.tripId, tripId)` on a uuid column → pg `22P02 invalid input syntax for type uuid`); `apps/web/src/server/eventStore.ts:75-80` (`readStream`, a second instance reached only after the seam — not the one producing the observed 500); `apps/web/src/app/api/trips/[tripId]/pages/[pageId]/route.ts:9,18` → `getPage`; `access/invites.ts` `revokeInvite`; `access/shares.ts` `revokeShare`; `savedDays.ts` (`/api/saved-days/[savedDayId]` GET/DELETE/publish and `/api/trips/[tripId]/saved-days/[savedDayId]`); rendering chain `apps/web/src/lib/apiClient.ts:114` (`data.error ?? res.statusText`; the 500 arrives with an empty body so `res.json()` fails and `statusText` wins) → `TripProvider.tsx:129-131` `setError(...)` → `TripBoardScreen.tsx:299-302` `<p role="alert">{error}</p>`. Unaffected: `[token]` routes and `[userId]` (text columns), and `history/[seq]` (`Number("abc")` → NaN → 404). No `.uuid()` validation of any route param exists; `DEMO_TRIP_ID` (`lib/demoTrip.ts:20`) is itself a UUID.
- **What is wrong:** signed in (cookie + curl): `GET /api/trips/not-a-uuid` 500; `/history`, `/pages`, `/pages/xyz`, `/access`, `/globals`, `POST /duplicate` all 500; with a valid trip, `GET/PATCH pages/not-a-uuid`, `DELETE invites/not-a-uuid`, `DELETE shares/not-a-uuid`, `POST saved-days/not-a-uuid`, and `/api/saved-days/not-a-uuid` GET/DELETE/publish all 500. Only `DELETE members/not-a-user` (a text column) 404s. Fifteen requests produced 33 pg errors in the server log, each a Sentry server-fault event. In the browser, `/trips/not-a-uuid` renders the header, the SaveLight saying "All changes saved", and the string **"Internal Server Error"** where the board goes; `/trips/not-a-uuid/pages/x` does the same in the notebook slot. Signed out is 401 (auth runs first), so it needs a session — any mistyped or truncated pasted link does it.
- **How it was verified:** dev-login, then curl with the session cookie against `next start` of the existing production build; probe scripts `G2-probe2.mjs`/`G2-probe3.mjs` and the verifier's `V-probe.mjs`/`V-ui.mjs` in the session scratchpad. Stable across three runs by two agents; the verifier saw eight `22P02` errors naming `trip_details.trip_id`, `pages.id`, `saved_days.id`, `trip_shares.id`, and the `role="alert"` with exactly "Internal Server Error" in the browser. The only `.uuid()` validators in `apps/web/src` are on request bodies (`readTools.ts:67`, `handleAskRequest.ts:188`, `lib/playbooks.ts:198`); no shared param parser exists; the demo id parses as a uuid under zod 3.25.76.
- **Suggested fix:** validate at the one seam every trip read passes through — `requireTripAccess` (`trip-access.ts:62`) returns the existing 404 shape when `!z.string().uuid().safeParse(tripId).success`, placed before the demo branch (the demo id is a UUID, so nothing changes for it). Same guard at the other two seams — `requireSavedDayRead` and `getPage` — plus `revokeInvite`/`revokeShare`; or one shared `parseIdParam(value)` helper. Three seams cover every instance. This is the same "client error surfaces as 500 + Sentry event" class as F-E04 — fix them in one PR.
- **Scope of the fix:** `trip-access.ts` + 4 server functions (or ~12 routes); no contracts, no migration. Check subset: `trip-access.int.test.ts`, `pages.int.test.ts`, `savedDays.int.test.ts`, `access/invites.int.test.ts`, `access/shares.int.test.ts`.
- **Test that should exist:** one int test per family, `not-a-uuid` → 404 — red today by throwing `22P02`.
- **Cross-reference:** F-E04, F-A03 (both add Sentry noise from client errors).
- **Do not:** catch the pg error and map `22P02` → 404 — that would also swallow a genuinely corrupt id in a stored row.
