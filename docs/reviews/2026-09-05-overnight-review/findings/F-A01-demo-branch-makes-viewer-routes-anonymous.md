# F-A01 — The demo-trip branch in `requireTripAccess` makes every viewer-minimum route anonymous, and one of them is an unbounded database write

- **Stream:** A Security · **Severity:** MEDIUM · **Confidence:** CONFIRMED (verified end to end)
- **Area:** `apps/web/src/server/access/trip-access.ts:80-85` (returns `{ userId: "demo-visitor", role: "viewer", detail }` when `isDemoTripId(tripId)`, **before** `auth()` at `:87`); `apps/web/src/app/api/saved-days/route.ts:23-26` (`requireTripAccess(body.tripId, "viewer")` → `saveDay(...)` → `savedDays.ts:157` `db.insert(savedDays)`); `apps/web/src/app/api/trips/[tripId]/pages/route.ts:8` → `pages-guard.ts:26` → `pages.ts:83` (seeds default pages, `onConflictDoNothing()` against a unique index); `proxy.ts:132` (matcher excludes `/api`); `lib/demoTrip.ts:20` (`DEMO_TRIP_ID` is a valid uuid); `db/schema.ts` (no `references()` anywhere — `saved_days.owner_id` is free text, `:226`); `handleAskRequest.ts:268-273` (the AI route already refuses the demo trip by hand before `guard()`).
- **What is wrong:** ADR-031 intended four anonymous *reads* (`GET /api/trips/:id`, `/history`, `/access`, `/history/:seq` — `trip-access.ts:69-71`) and states "the only database work in the whole demo is the clone" (`ADR-031:186`). The seam is generic, so every caller that asks for `viewer` inherits the anonymous answer:
  1. **`POST /api/saved-days` — unbounded anonymous write.** With no cookie: `GET /api/trips/00000000-0000-4000-8000-00000000d000` yields `days[].dayId`; `POST /api/saved-days {"name":"x","tripId":"<demo>","dayId":"<id>"}` returns 201 and inserts a `saved_days` row with `owner_id = "demo-visitor"`. No quota applies (`consumeQuota` is wired only to `/ask` and `/geocode`). Rows are orphans forever — no user can list or delete them.
  2. **`GET /api/trips/<demo>/pages` — one-shot anonymous write.** Seeds the two default notebook pages for the demo id once; then `GET /pages/<id>` is an anonymous read of them. Bounded by the unique index, but it is a DB write on a path ADR-031 says has none.
  `GET /api/trips/<demo>/globals` is also anonymous (derived, harmless). No test covers the demo id on either route — the 401 tests at `saved-days/route.int.test.ts:49-52` and `pages/route.int.test.ts:36-41` use real trips; `demoTrip.test.ts`'s "pg throws" guard checks the demo module's import graph, not these routes.
- **Suggested fix:** make the demo answer opt-in: `requireTripAccess(tripId, minimum, { allowDemo: true })` used only by the four ADR-031 routes (and the pages GET if the demo notebook is meant to be public — decide, and if so seed its pages from the fixture rather than the table). Everything else gets 401 for the demo id, which is what `/ask` already does by hand. Then delete the hand-rolled refusal in `handleAskRequest.ts:268-273` in favour of the seam. Cleanup: `DELETE FROM saved_days WHERE owner_id = 'demo-visitor'` after deploy.
- **Scope of the fix:** `trip-access.ts`, `pages-guard.ts`, 4–6 routes, `handleAskRequest.ts`. No contract change, no migration. Check subset: `apps/web` typecheck + `demoTrip.int.test.ts`, `saved-days/route.int.test.ts`, `pages/route.int.test.ts`, `ask/route.int.test.ts:280`.
- **Test that should exist:** unauthenticated `POST /api/saved-days` with the demo trip id → 401 and `saved_days` count unchanged; unauthenticated `GET /api/trips/<demo>/pages` → 401 (or 200 with no row written, if made public) and `pages` count unchanged. Break by removing the opt-in flag; watch both go red for that reason.
- **Cross-reference:** ADR-031, KI-079 (the `/ask` special case's rationale), AGENTS.md invariant 6c, F-A02.
- **Do not:** add `auth()` inside `saveDay` (the route is the boundary); remove the demo branch wholesale (the four public reads depend on it).
