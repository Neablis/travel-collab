# F-B02 — `narrow` is the only place a filter dimension gets meaning, and nothing ties it to `FilterDimension`; a new dimension is accepted, stored and rendered as a control while silently ignored

- **Stream:** B Notebook · **Severity:** MEDIUM (latent — the framework hole a new dimension falls through) · **Confidence:** CONFIRMED (verified)
- **Area:** `packages/pages/src/select.ts:32-39` (`WidgetFilterValues` hand-written interface, not derived from `FILTER_VALUE_SCHEMAS`), `:124-137,159-164,197-198,223-226` (`narrow` names each dimension by hand; its own comment at `:106-108` calls "a control that says narrowed while the widget renders wide" the worst of three answers); `packages/contracts/src/pages.ts:65,202-209` (`FilterDimension` enum and `FILTER_VALUE_SCHEMAS satisfies Record<FilterDimension,…>` — total); `packages/pages/src/filters.ts:77,92` (`INPUT_TYPE_OF`/`LABEL_OF` are `Record<FilterDimension,…>` — total), `:134` (`filterParams` derives the params schema, so a new dimension is accepted and kept); `apps/web/src/components/pages/editor/widgetBind.tsx:176-187` (`optionsFor`'s `default:` is the *tags* branch — an unknown input type gets "Every stop" plus the trip's tag list); `select.test.ts` has one `it` per dimension and no sweep over `FilterDimension.options`.
- **What is wrong:** add `currency` to the enum: three `Record`s go red (good), the params schema accepts it, the chrome renders a control, `insertWidget` allows it — and `narrow` ignores it. Nothing compiles red for the one place that matters; no test fails. The same shape is why lighting up the already-declared `person` dimension is two uncaught edits (`widgetBind.tsx:140-189` case, `select.ts:124,159-164` predicate).
- **Suggested fix:** `export type WidgetFilterValues = { [K in FilterDimension]?: z.infer<(typeof FILTER_VALUE_SCHEMAS)[K]> }`; in `narrow`, a `const handled: Record<FilterDimension, true>` literal beside the predicates so a new member fails to compile; in `optionsFor`, an explicit `case "tags"` and `default: { const _: never = kind; … }`.
- **Scope of the fix:** `select.ts`, `widgetBind.tsx`. No contract change. Check subset: `pnpm --filter @tc/pages test`, `apps/web` unit for `widgetBind`.
- **Test that should exist:** `select.test.ts` sweep — for every `FilterDimension`, binding a value that matches nothing on the selection fixture yields a selection different from `narrow(trip, globals, {})` (or `unbound`). Break by deleting one predicate in `narrow`.
- **Cross-reference:** ADR-039 decision 3 ("legality is declared, never assumed" — semantics are still assumed), proposed widget rule 4 in the README.
- **Do not:** fix by adding a dimension-specific branch; fix the totality.
