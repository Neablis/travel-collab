# F-B01 — The server accepts any widget name and any params on the page write path; the `attribute` allow-list and filter legality are enforced only in the browser

- **Stream:** B Notebook · **Severity:** MEDIUM · **Confidence:** CONFIRMED (verified end to end)
- **Area:** `apps/web/src/app/api/trips/[tripId]/pages/[pageId]/route.ts:20` (`UpdatePageInput.safeParse`) → `apps/web/src/server/pages.ts:97` (stores `input.content` verbatim); same for POST at `pages/route.ts:23-26`; `packages/contracts/src/pageDoc.ts:43-44` (`MacroNode.attrs`: `name: z.string().min(1)`, `params: z.record(z.unknown())`); the registry walk that *would* check name and params — `walkForError` in `apps/web/src/server/ai/pageTools.ts:178-207` — has one caller, `validateComposedPage` (`:173`), reached only from the AI path (`handleAskRequest.ts:744`), which returns nodes to the client rather than writing; client-side enforcement at `packages/pages/src/insert.ts:94` and render-time "bad params" chip at `registry.ts:84-85` → `MacroView.tsx:96`; `route.int.test.ts` never sends a `macro` node (`:203-214` covers a bad *title*).
- **What is wrong:** `PATCH {content: …{type:"macro", attrs:{name:"attribute", params:{field:"account.email"}}}}` is 200 and persisted; so are `cost{person:"x"}` and `nope.nope{}`. ADR-039 decision 6 and spec §3 describe the `attribute` allow-list as what "stops it becoming a field browser"; today that is a browser convention. ADR-037 decision 4 ("no way to put a widget into a document that skips validation") holds for every *insert* path and is bypassed by the *write* path. Any editor-role client, including a future compose tool or a stale build, can store a document the renderer shows as "bad params".
- **Suggested fix:** lift `walkForError` out of `pageTools.ts` into `apps/web/src/server/pages.ts` (or `server/pageDocCheck.ts` beside it) and call it from POST/PATCH after the `PageDoc` parse; 400 with the same message the AI path returns. Do it in the same change as F-B09/F-C05 (re-stamp `v` and serialise on write) — same insertion point, same tests.
- **Scope of the fix:** `route.ts` ×2, `server/pages.ts` (or new module), `pageTools.ts` (import moves), `route.int.test.ts`. No contract change, no migration. Check subset: pages route int tests + `server/ai` unit.
- **Test that should exist:** PATCH a document containing `attribute{field:"account.email"}` → 400; PATCH `cost{kind:"booked"}` → 200. Break by removing the walk; watch the first go green wrongly.
- **Cross-reference:** ADR-037 decision 4, ADR-038 decision 4 (read stays permissive — leave it), ADR-039 decision 6, F-A02, F-B09.
- **Do not:** put registry validation inside `PageDoc` — `packages/contracts` cannot import `@tc/pages` (`pageDoc.ts:376-383` says why). Do not refuse on the read path.
