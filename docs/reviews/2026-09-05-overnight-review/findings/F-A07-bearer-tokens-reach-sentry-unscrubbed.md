# F-A07 — Share and invite bearer tokens reach Sentry unscrubbed on every traced request; no `beforeSend` exists anywhere

- **Stream:** A Security + D Infra (A07 and D02 merged) · **Severity:** MEDIUM · **Confidence:** CONFIRMED mechanism (verified in the SDK source; not observed in a live Sentry event)
- **Area:** `apps/web/src/instrumentation.ts:13` (`onRequestError = Sentry.captureRequestError`) → `node_modules/@sentry/nextjs/build/cjs/common/captureRequestError.js:15` (`request_path: request.path`, raw, token included); `apps/web/sentry.shared.ts:148-161` (`tracesSampleRate` default 1.0 at `:114-118`; `sendDefaultPii: false` at `:160`, which strips IPs/cookies/headers but not URL paths or custom context); `sentry.server.config.ts`, `sentry.edge.config.ts`, `src/instrumentation-client.ts` — zero occurrences of `beforeSend`, `beforeSendTransaction` or `beforeBreadcrumb` in any of the three inits; `instrumentation-client.ts:10,33-34` (Session Replay on, records `location.href`; `captureRouterTransitionStart` records URLs); `next.config.ts:177-201` hardens `Referrer-Policy` for `/s` and `/invite` (and notes `/signin?callbackUrl=%2Finvite%2F<token>` carries the token too) — the browser side is handled, the telemetry side is not.
- **What is wrong:** ADR-026/027 make the bearer token *the whole secret*. Every `GET /api/shares/<token>`, `/api/invites/<token>/accept`, and every `/s/<token>` page view is a traced transaction at 100% sampling, and every unhandled error on those routes ships the path. Tokens sit in a third-party SaaS for the retention period. Reproduction: throw inside `s/[token]/page.tsx`, open the event, read `contexts.nextjs.request_path`. SECURITY.md accepts bearer-in-URL for recipients but says nothing about the operator-side telemetry copy.
- **Suggested fix:** one `scrubUrl(s)` in `sentry.shared.ts` masking `/(s|invite)/[^/?#]+`, `/api/(shares|invites)/[^/?#]+` and `callbackUrl=` values; apply via `beforeSend`, `beforeSendTransaction`, `beforeBreadcrumb` in `sharedSentryOptions` (all three inits spread it) to `contexts.nextjs.request_path`, `request.url`, transaction names and breadcrumb `data.to`/`from`; Replay `beforeAddRecordingEvent` or `maskAllText`-style URL scrub; one sentence in SECURITY.md and in ADR-032's "what it does not collect" list.
- **Scope of the fix:** `sentry.shared.ts` (+ `sentry.shared.test.ts`), `instrumentation-client.ts`, SECURITY.md, ADR-032 amendment. No contracts. Check subset: `pnpm --filter web exec vitest run -c vitest.unit.config.ts sentry.shared.test.ts` + `telemetry.int.test.ts`.
- **Test that should exist:** unit test feeding events/transactions/breadcrumbs with each URL shape and asserting the token is gone; extend `telemetry.int.test.ts` to assert a fixture token never appears in an envelope.
- **Cross-reference:** ADR-026, ADR-027, ADR-032, SECURITY.md.
- **Do not:** lower `tracesSampleRate` as the fix (ADR-032's AI dashboard depends on it); disable Sentry on those routes (they are the pages most worth error signal). First check whether Sentry project-level data scrubbing already masks these paths — if so this drops to belt-and-braces, but the in-repo scrub should still exist so the property does not depend on a dashboard setting.
