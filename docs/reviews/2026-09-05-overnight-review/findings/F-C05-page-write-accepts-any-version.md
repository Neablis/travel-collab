# F-C05 — The page write path accepts any `v` and never migrates on write, so one bad PATCH locks a notebook read-only with no in-app recovery

- **Stream:** C Versioning (+ B09, same fix) · **Severity:** LOW · **Confidence:** CONFIRMED (verified; exposure narrower than first stated)
- **Area:** `packages/contracts/src/pageDoc.ts:346` (`v: z.number().int().positive().default(1)`, no ceiling; the comment at `:339-344` says the default "stops being safe the moment a second version does" — v2 exists at `:505-508`); `apps/web/src/app/api/trips/[tripId]/pages/[pageId]/route.ts:20` → `packages/contracts/src/pages.ts:301` (`content: PageDoc.optional()`) → `apps/web/src/server/pages.ts:97` (stores `input.content` as-is, no `migratePageDoc`); reader `storedPageDoc.ts:43-49` → `PageScreen.tsx:318+` (read-only, no Edit toggle).
- **What is wrong:** any editor-role client that sends `v: CURRENT+1` produces a row every current build refuses forever; the only repair is a database edit. A body with no `v` (permitted on purpose, `pages.ts:288-290`, exercised by `route.int.test.ts:69,103`) is stored as `v: 1` — harmless today only because the v1→v2 step is idempotent on v2 content (`page-doc.test.ts:99`); the first non-idempotent step corrupts every v-less row. Exposure is narrow: every first-party writer stamps `v` through `migratePageDoc` (`storedPageDoc.ts:46`, `pageTools.ts:167`, `apiClient.ts:844`), so only a hand-crafted request by an editor on their own trip reaches it.
- **Suggested fix:** in the two pages routes (or `server/pages.ts`), after the `PageDoc` parse: refuse `v > CURRENT_PAGE_DOC_VERSION` with 400, then store `serializePageDoc(migratePageDoc(parsed))` so rows converge to the current version. Do this in the same change as F-B01 (registry validation on write) — it is the same insertion point.
- **Scope of the fix:** `server/pages.ts` or the two routes; contracts unchanged unless the write schema gains a `.refine` (then CHANGELOG). Check subset: `pages` route int tests, `page-doc.test.ts`.
- **Test that should exist:** PATCH with `v: CURRENT+1` → 400; PATCH with a v1 body → stored row is `v: CURRENT` with migrated names.
- **Cross-reference:** ADR-038 decision 2, F-B01, F-B09.
- **Do not:** make `Page.content` strict on read (`pages.ts:221-238` explains why).
