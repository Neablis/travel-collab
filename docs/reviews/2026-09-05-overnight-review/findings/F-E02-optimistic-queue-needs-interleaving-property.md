# F-E02 — The optimistic send queue has produced six KIs and two review findings by line-fixes; it has no property test over interleavings

- **Stream:** E Maintainability · **Severity:** MEDIUM · **Confidence:** CONFIRMED (verified; the two open symptoms are already KI-5 and KI-90 — the net-new content is the guard)
- **Area:** `apps/web/src/components/trip/context/optimistic.ts` (216 lines), `TripProvider.tsx:315` (`await sendTripCommand(command)`) then `:322` (unconditional `setOptimistic(prev => prev ? { confirmed: result.value, pending: [] } : prev)` — KI-90's line); `optimistic.test.ts` (0 uses of fast-check, while 10 other test files use it); no `beforeunload`/`pagehide`/`keepalive` anywhere in `apps/web/src` (KI-5 has no mitigation).
- **What is wrong:** KI-5, 36, 42, 55, 70, 90 and 2026-08-28 §1.1/§1.4 are all "an accepted unit vanished with no failure record". Each was fixed as a line (KI-70's ref read, KI-42's retention) and the next window opened beside it — KI-90 is literally the same line after the `await`. Every test in `optimistic.test.ts` is an example the author already imagined; `TripProvider.test.tsx:719-735` covers only the same-tick KI-70 half.
- **Suggested fix:** one fast-check property over a model of the queue — for any interleaving of `enqueue` / `confirmHead` / `failHead` / history-reconcile, every accepted unit is either confirmed, retained in `pending`, or present in `failure`. It would have caught KI-42, 55, 70 and 90 at once, and it forces the one product decision KI-90 defers (gate edits during a history command, or re-predict the queue on top of the reconciled state). Add a `witness` floor per `docs/guidelines/testing.md`.
- **Scope of the fix:** `optimistic.ts` (+ possibly a small "adopt outcome, re-predict pending" reducer), `optimistic.test.ts`, `TripProvider.tsx:305-325`. No contracts. Check subset: `pnpm --filter web exec vitest run -c vitest.unit.config.ts src/components/trip/context`.
- **Test that should exist:** the property above; break it by restoring the unconditional `pending: []` and watch it fail on an interleaving with a queued edit.
- **Cross-reference:** KI-5 (hub, open), KI-90 (open, "filed rather than fixed"), KI-36/42/55/70 (resolved), ADR-012/013, 2026-08-28 review §1.1/§1.4.
- **Do not:** fix KI-90 as another line without the property — that is how KI-70 produced KI-90.
