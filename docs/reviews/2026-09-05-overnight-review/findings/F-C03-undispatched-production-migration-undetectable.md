# F-C03 — A merged-but-undispatched production migration is undetectable, and the PR template does not prompt for one

- **Stream:** C Versioning + D Infra (merged: C03 and D01 are one finding) · **Severity:** MEDIUM · **Confidence:** CONFIRMED mechanism (verified); whether production is *currently* behind is unknown from the repo
- **Area:** `.github/workflows/migrate-production.yml:21-25` (`workflow_dispatch` + typed confirm only); `apps/web/scripts/vercel-build-migrate.mjs:9` (runs only when `VERCEL_ENV === "preview"`); `.github/workflows/ci.yml` (no job on `push` to `main`, no drizzle-kit); `.github/PULL_REQUEST_TEMPLATE.md` (no line matching `migration` or `drizzle`); the only health route is `apps/web/src/app/api/health/ai-mode/route.ts:13-15` (reports the AI flag, not DB state); `apps/web/drizzle/meta/_journal.json` (16 entries, last `0015` at 2026-09-02T01:21Z); `0014` adds `saved_days.deleted_at` (read at `savedDays.ts:233`), `0015` adds `users.display_name/home_airport/distance_unit` (read at `users.ts:147+`).
- **What is wrong:** production deploys on merge; migrations apply on a human dispatch (ADR-004, decided 2026-08-27 for cost reasons — deliberate). `AGENTS.md:335-341` makes "say so in the PR body" the sole control, and the template it mandates has no field for it. After merge nothing — not the build, not a health probe, not CI — says the journal is ahead of `drizzle.__drizzle_migrations`. Code reading `deleted_at` or `distance_unit` 500s on a database that has not had 0014/0015 applied, and users find out first. `docs/STATUS.md:1007-1010` calls this "the thing most likely to be missed"; whether 0012–0015 were dispatched is not recorded anywhere in the repo.
- **Suggested fix, smallest-loud first:** (a) PR template, under *Verification*: `Migration: <none | 00NN_tag> — dispatched via migrate-production? [ ]`. (b) A migration-state check beside the existing `api/health/ai-mode` route: compare `count(*)`/`max(created_at)` from `drizzle.__drizzle_migrations` against `_journal.json` and report drift (JSON body + Sentry warning). (c) `.github/workflows/pending-migration-check.yml` on `push` to `main` with `paths: ['apps/web/drizzle/**']`, one read-only `psql` against `secrets.PRODUCTION_DATABASE_URL`, failing when the journal is ahead — a red X on the merge commit, ~1 billed minute, only on migration merges.
- **Scope of the fix:** template, one new route (or extend the health route), one workflow, `environments-and-deploys.md`. No contracts, no migration. Check subset: unit test of the comparison over a fixture journal; run the workflow once by hand.
- **Test that should exist:** unit test of journal-vs-applied comparison with a fake journal and a fake `max(created_at)`.
- **Cross-reference:** ADR-004, `docs/guidelines/ci-cost-and-capacity.md:227-263`, `TODO.md:181-183`, `docs/milestones/M5-design-foundations.md:163` (stale: says migrations are "automatic"), F-D03.
- **Do not:** reintroduce migrate-on-build for production, or migrate at cold start — the 2026-08-27 call was explicit and this finding asks for a detector, not a policy change.
- **First action for the fixer:** ask Mitchell (or read the Actions history) whether 0012–0015 have been dispatched; if not, that is production incident work before any of the above.
