# F-C04 — Kept days (`saved_days.stops`) carry no version and `SavedStop` has no defaults; the first required-field addition hides every existing Playbook

- **Stream:** C Versioning · **Severity:** MEDIUM · **Confidence:** CONFIRMED (verified)
- **Area:** `packages/contracts/src/saved.ts:23-32` (`SavedStop`: `kind`, `tags`, `anchors`, `cost` all required, no `.default()`); `apps/web/src/server/savedDays.ts:80-88` (`fromRow` drop-and-log), `:234-238` (list filters nulls); `apps/web/src/server/db/schema.ts:234` (`jsonb` with compile-time `$type` only; comment at `:228-233` forbids parsing elsewhere); ADR-040 is `Status: Draft` and unbuilt.
- **What is wrong:** KI-71's fix made an unreadable row fail closed (good), but there is no migration mechanism at all for this jsonb value — unlike `PageDoc` (`v` + migration chain) and event payloads (`.default()` on every post-v1 field, `activity.ts:163-166`). Add one required `SavedStop` field (a second time zone, a money-model change, any ADR-040 follow-on that lands *inside* a stop) and every existing saved day disappears from its owner's library and from Discover until someone writes a backfill in the style of `scripts/backfill-saved-day-cities.mjs`. Rows survive, so it is recoverable — by an operator who reads `console.error`. Note: ADR-040's `source_day_id` is a nullable *column* (ADR-040:63), not a `SavedStop` field, so it would not itself trigger this.
- **Suggested fix:** adopt the event-payload rule for `SavedStop` in the contract file's header — every field added after today carries `.default()` — and add `v` to the stored `stops` value now while there is one version (a `{ v: 1, stops: [...] }` wrapper parsed in `fromRow`, with a one-shot migration on read for v-less rows). Write it into ADR-040's consequences before its migration lands.
- **Scope of the fix:** `saved.ts` (+ CHANGELOG), `savedDays.ts` (`fromRow`, the two writers), `playbooks.ts:229-245` (the duplicate parse — see F-F05, fold into one helper); one SQL migration only if the wrapper is applied to existing rows rather than migrated on read. Check subset: `savedDays.int.test.ts`, `api/playbooks/**/route.int.test.ts`.
- **Test that should exist:** `savedDays.stops.int.test.ts` already has "row missing kind/tags is dropped and logged"; add its inverse for any newly defaulted field: a pre-field row parses and renders.
- **Cross-reference:** KI-071 (resolved), ADR-029, ADR-040 (draft), F-C01, F-F05.
- **Do not:** parse `row.stops` anywhere except `fromRow` (and the shared helper F-F05 proposes).
