# F-B03 — `serializePageNode` returns `unknown` with no exhaustive default, so a future `PageNode` member would be written as `null` and lock the page

- **Stream:** B Notebook · **Severity:** LOW (latent; no case is missing today) · **Confidence:** CONFIRMED (verified by compiling a probe against the repo's tsconfig)
- **Area:** `packages/contracts/src/pageDoc.ts:569-587` (`serializePageNode(node: PageNode): unknown`, switch with no `default`), `:560-564` (`serializePageListContentNode`), `:118-131` (`KNOWN_NODE_TYPES` hand list, restated by hand in `page-doc.test.ts:16-33`); `tsconfig.base.json` sets `strict` and `noUncheckedIndexedAccess` but not `noImplicitReturns` — a switch missing a case that returns `unknown` compiles with zero errors (probe confirmed; `--noImplicitReturns` flags it TS7030); the repo already knows this: `BlockView.tsx:53-59` and `MacroView.tsx` add `never` defaults with a note saying so; `ReadOnlyPageDoc.tsx:59-66,100-151` switches return `ReactNode` (includes `undefined`) — a new node renders as nothing there.
- **What is wrong:** a missing `case` compiles, returns `undefined`, `toStoredPageDoc` (`storedPageDoc.ts:81-85`) writes it, `JSON.stringify` turns the array element into `null`, `tagUnknownNode` needs `isNodeLike` (`:133-140,152-154`) so `null` is a parse error → `unreadable` → locked page. No test can catch it: the round-trip generator produces only types *outside* `KNOWN_TYPES` (`page-doc.test.ts:58-63`) and the goldens are fixed.
- **Suggested fix:** `default: { const exhaustive: never = node; return exhaustive; }` in both serialisers and in `ReadOnlyPageDoc`'s two switches; derive `KNOWN_NODE_TYPES` from the unions' literal types (or assert equality against `PageNode.options.map(o => o.shape.type.value)` in a test). Consider `noImplicitReturns: true` in `tsconfig.base.json` — measure the fallout first.
- **Scope of the fix:** `pageDoc.ts`, `ReadOnlyPageDoc.tsx`, optionally `tsconfig.base.json`. Not a wire change. Check subset: `pnpm --filter @tc/contracts typecheck test`, web typecheck.
- **Cross-reference:** ADR-038 decision 5, proposed widget rule 8 in the README, F-E06 (packages are unlinted, so no lint rule can enforce this either today).
