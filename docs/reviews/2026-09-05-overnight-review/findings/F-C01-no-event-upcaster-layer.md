# F-C01 — There is no event upcaster layer, and the event union's shape blocks adding one without touching every reader

- **Stream:** C Versioning · **Severity:** MEDIUM · **Confidence:** CONFIRMED (independently verified; Zod behaviour executed)
- **Area:** `packages/contracts/src/trip.ts:206-222` (`TripEvent = z.discriminatedUnion("type", [...])`, every member `version: z.literal(1)`), `activity.ts:169-193`, `history.ts:44-58`; the five parse sites `packages/domain/src/trip/project.ts:6`, `detail.ts:64`, `history.ts:22` and `:44` (via the alias `TripEventSchema.parse`), `apps/web/src/server/projections.ts:18`; `version: 1` literal emitted at 34 sites (`diff.ts` ×16, `decide.ts` ×18); exhaustive `switch (event.type)` in `evolve.ts:57`, `project.ts:11`, `history.ts:180`, `projections.ts:23`, `cloneTrip.ts:208`.
- **What is wrong:** ADR-003 (`:47-48`) promised "versioned events and upcasters so old logs replay", and three guidelines describe the procedure as if it exists (`docs/guidelines/building-the-parts.md:23-25` "bump its `version`, keep the old schema, write `upcast(vN) → vN+1`. Replay always upcasts"; `quality-enforcement.md:11`; `connecting-the-parts.md:37`). Only the version *literal* exists; nothing reads `env.version` except to match `1`, and no `upcast` symbol exists anywhere. Worse, the prescribed procedure is structurally impossible as written: `TripEvent` discriminates on `type` alone, and Zod 3 rejects a second option with the same `type` (verified: `discriminatedUnion("type",[A1,A2])` throws `Discriminator property type has duplicate value A`). So the first non-additive payload change forces either a plain `z.union` (loses discriminated errors and `describeEvent`'s shape) or a new `type` string, plus a fold-time upcast step that does not exist, plus edits to all five switches and to `diffTripStates`/`decide`. All three real schema changes to date (M2 envelope, M11 `forkedFrom`, M18 `kind`/`tags`) were additive-with-`.default()` — that pattern works and is the only one available.
- **What happens today when a stored row does not parse:** it is never skipped. `GET /api/trips/:id` still works (reads the projection), but every command, history read, point-in-time read and pinned share throws a `ZodError` → 500. `rebuildProjections` aborts on the first bad row of *any* trip, and the error carries neither `streamId` nor `seq` (KI-2026-08-30-e:5 recorded this blast radius once already).
- **Suggested fix:** (1) Consolidate the five `TripEvent.parse({type, version, payload})` sites into one `parseStoredEvent(env)` in `packages/domain`. (2) Write the rule down as an ADR amendment: additive-with-`.default()` is the preferred path; when it is not enough, the upcaster is a per-`type` `upcast(version, payload) → current payload` step inside `parseStoredEvent`, applied *before* the discriminated-union parse — which is why the union can stay discriminated on `type` with a single current version per member. (3) Amend the three guidelines to describe that, not the impossible "keep the old schema as a sibling option".
- **Scope of the fix:** contracts (`trip.ts`, CHANGELOG entry), domain (`history.ts`, `project.ts`, `detail.ts`), server (`projections.ts`), three guideline files, ADR-003 amendment. No migration. Check subset: `pnpm --filter @tc/domain test`, `pnpm --filter @tc/contracts test`, `apps/web` `projections.int.test.ts`.
- **Test that should exist:** a domain test folding an envelope with `version: 2` through the upcaster to the same state as its v1 equivalent (fails today with "Invalid literal value, expected 1"). Break it by removing the upcast step.
- **Cross-reference:** ADR-003, ADR-008 (money change is the named future trigger), ADR-036 (page events will inherit this), KI-2026-08-30-e, F-C02, F-C04.
- **Do not:** rewrite stored rows in place; switch `TripEvent` to `z.union` casually; add version-2 members as siblings in the discriminated union (it throws at module load).
