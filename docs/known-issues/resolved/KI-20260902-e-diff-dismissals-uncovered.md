### KI-2026-09-02-e — `diffTripStates` step 7 (conflict dismissals) has no test coverage at all — RESOLVED

- **Severity:** correctness risk, unproven. The code looks right on reading; nothing proves it, and it sits on the time-travel path.
- **Area:** `packages/domain/src/trip/diff.ts` lines 171-181 — the two loops that reconcile `dismissedConflictIds` between working and target state, emitting `ConflictUndismissed` and `ConflictDismissed`.
- **How it was found:** the first real run of `pnpm mutate` (`scripts/mutate.mjs`, added the same day). `pnpm mutate packages/domain/src/trip/diff.ts` — 29 seconds, 78.29% total score, **114 killed, 25 survived, 8 no-coverage**. All eight no-coverage mutants are in step 7. Stryker deleted both loop bodies, inverted both conditions and blanked both event types, and **no test ran the lines at all**.
- **Why it matters:** `diffTripStates` is how time travel works — restoring an earlier state is expressed as the events that get you there. If step 7 is wrong, dismissing a conflict and then undoing past it either re-raises a conflict the user dismissed or silently keeps one dismissed that should be back. Neither fails loudly. `diff.ts` is also KI-1's home, which is the reason the test-overhaul plan named it as a mutation target in the first place.
- **The 25 survived mutants elsewhere in the file are a separate question** and are NOT all defects — a surviving mutant can mean a line nothing needs. They are worth a read, and they are not what this entry is about. The eight with no coverage are unambiguous: no test executes that code.
- **Fix path:** two unit tests in `packages/domain/test/diff.test.ts` — a working state that dismissed a conflict against a target that had not (expect `ConflictUndismissed`), and the reverse (expect `ConflictDismissed`). Then re-run `pnpm mutate packages/domain/src/trip/diff.ts` and confirm the no-coverage count is zero. Small, self-contained, good ki-sweep material.
- **Why not fixed here:** found while proving the instrument works, in a PR that adds the instrument. Fixing it inside that PR would have meant the tool's first finding never got written down as a finding — and the measurement above is the thing a future session needs in order to re-measure without re-deciding, which is what the test-overhaul plan asked for.
- **Cross-reference:** `scripts/mutate.mjs`, `docs/plans/test-overhaul/phase-5-prune.md` Task 5.3 (which named `diff.ts` as a mutation target and said to record before/after), KI-1, `docs/guidelines/testing.md` §3.
- **Fix:** coverage only — **`diff.ts` was not changed, and step 7 was correct as written.** Three tests in `packages/domain/test/diff.property.test.ts` (`diffTripStates conflict dismissals (step 7, KI-2026-09-02-e)`) build the two states either side of a real dismissal through the command path (`decideTripCommand` + `evolveTrip` over two overlapping activities, so the id is a genuine content-derived conflict id) and assert the exact event either way, plus the round trip: current-dismissed vs target-not → `ConflictUndismissed`; the reverse → `ConflictDismissed`; and both states holding the *same* dismissal → no events. The third is not redundant with the generated `diff(x, x) is empty` property — no generated history reaches a non-empty `dismissedConflictIds`, which is the whole reason step 7 was dark.
- **Proven by:** each test broken red first, individually, against the loop it protects. Deleting the `ConflictUndismissed` push → `AssertionError: expected [] to deeply equal [ { …(3) } ]`; deleting the `ConflictDismissed` push → the same shape on the second test; forcing the first loop's condition to `if (true)` → `expected [ { …(3) }, { …(3) } ] to deeply equal []`, an undismiss/re-dismiss pair churned on a no-op revert. Notably the 300-run round-trip property stayed green under all three, which is the measurement confirming it never reaches step 7. Restored, `pnpm --filter @tc/domain exec vitest run test/diff.property.test.ts` → 14 passed; `pnpm --filter @tc/domain typecheck` clean.
- **Re-measured** with `pnpm mutate packages/domain/src/trip/diff.ts`: **78.29% / 8 no-coverage** at filing, **77.63% / 16 no-coverage** as re-measured on 2026-09-05 (same 16 all in step 7 — the count differs from the entry above, the location does not), now **86.84% total, 127 killed, 20 survived, 0 no-coverage.** One step-7 mutant survives and is *equivalent*, not a gap: `if (true)` at `diff.ts:178` (the second loop's guard). `evolveTrip` already returns the same state for a `ConflictDismissed` whose id is present (`evolve.ts:126`), and `push()` drops events that do not change state, so the guard is a fast-path with no observable effect. No test can kill it, and none should be written to try.
