### KI-2026-09-02-c — `packages/*` have no ESLint at all, so the test-quality wall covers `apps/web` only — RESOLVED

- **Severity:** cleanup (no known defect; found while landing the wall next door).
- **Area:** all six workspace packages — `contracts`, `domain`, `pages`, `factories`, `fixtures`, `predict`. None has an `eslint.config.*`; none has a `lint` script. The root `pnpm lint` is `pnpm --filter web lint` plus the four `scripts/` walls.
- **What is wrong:** the test-quality wall added 2026-09-02 (`eslint-plugin-testing-library`, `eslint-plugin-playwright`, the no-presentation-assertion rule) is configured in `apps/web/eslint.config.mjs` and therefore stops at `apps/web`. **767 tests are outside it** — 229 in `packages/domain`, 354 in `packages/factories`, 152 in `packages/contracts`, 32 in `packages/pages`. A test in `packages/pages` may assert a class name, reach into `container`, or leave a `screen.debug()` in, and nothing says so.
- **How much it actually matters, honestly:** less than the count suggests. Most of those tests are pure-function tests with no DOM to reach into — `no-node-access` cannot fire on `packages/domain`. `packages/pages` is the real exposure: it has `fast-check` and DOM-adjacent tests, and it is where a future component-shaped test would go. The wall's *presentation* half is the one with a live gap.
- **The wider point:** this is the same species as KI-51 (the colour wall blind to untracked files) and KI-2026-08-30-b (`eslint src` blind to `e2e/`) — a guard whose scope is narrower than its name suggests, where nothing reports the difference. Both of those were found by looking, not by failing.
- **Fix path:** a shared flat config at the repo root that every package extends, plus a `lint` script per package and a root `pnpm -r lint`. That is a structural change to six packages and belongs in its own PR; doing it inside the wall's own PR would have hidden it. Check what it turns up before assuming it is clean — `apps/web`'s first pass found 228 findings in a suite everyone believed was tidy.
- **Cross-reference:** KI-2026-09-02-b (the grandfathered backlog inside `apps/web`), KI-2026-08-30-b (resolved), KI-51 (resolved), `docs/plans/test-overhaul/phase-7-guidelines.md` Task 7.1.

- **Re-verified 2026-09-25 (overnight sweep):** still true. `ls packages/*/eslint.config.* eslint.config.*` finds nothing (no package config and no root config), and `grep '"lint"' packages/*/package.json` finds nothing. The six packages hold 112 test files, from which I did not recount individual tests: contracts 26, domain 31 (under `packages/domain/test/`, not `src/`), factories 6, fixtures 10, pages 39, predict 0. `pnpm arch` does now cruise `packages/*/src`, but that checks dependencies, not test quality, so it does not narrow this.
- **Resolved 2026-09-25 (overnight sweep).** Reproduced first: `ls packages/*/eslint.config.* eslint.config.*` found nothing, `grep -c '"lint"' packages/*/package.json` was `0` for all six, and `pnpm --filter @tc/pages lint` printed `[ERR_PNPM_RECURSIVE_RUN_NO_SCRIPT] None of the selected packages has a "lint" script`. The fix: a root `eslint.config.mjs`, scoped by `files` to `packages/*/**`, which each package's new `lint` script (`eslint --max-warnings 0 .`) finds by ESLint 9's upward config lookup; root `pnpm lint` now starts with `pnpm -r lint` (every workspace package, `web` included) instead of `pnpm --filter web lint`. It carries `@typescript-eslint`'s `flat/recommended` (what `next/typescript` extends) with `apps/web`'s two local settings, `reportUnusedDisableDirectives: "error"`, `@testing-library`'s `flat/dom` rules on package tests with `no-debugging-utils` promoted to error, and `apps/web`'s no-presentation-assertion selectors. The design-system element/colour walls, the fetch wall and the import walls are deliberately absent — they are about `apps/web`'s UI and server boundaries, and package boundaries are `pnpm arch`'s. `eslint`, `@typescript-eslint/parser`, `@typescript-eslint/eslint-plugin` and `eslint-plugin-testing-library` became root devDependencies at the versions `apps/web` already resolved, so the lockfile gained importer entries but no new package (it did dedupe `ignore` 7.0.5 → 7.0.9 under `@typescript-eslint/eslint-plugin`).
  **The count, as the entry asked, before assuming it clean: 239 files linted, 10 findings, all `@typescript-eslint/no-unused-vars`** — nowhere near `apps/web`'s 228, because no package test touches the DOM (every package's vitest runs in the `node` environment and none imports `@testing-library`). 9 were the omit-a-key idiom `const { dayId: _dayId, ...rest } = x` (8 in `packages/contracts/test/`, 1 in `packages/fixtures/src/bundle/fromTrip.test.ts`); 1 was `SEASONS` in `packages/fixtures/src/bundle/lint.ts`, a value used only to derive a type, rewritten as the literal union it spelled (type-only, behaviour-free). After that, zero; nothing grandfathered, no directives added.
  **Proof.** `scripts/check-lint-wall.mjs` gained a second lane (root eslint, root config, seam `LINT_WALL_PACKAGES_ESLINT_CONFIG`) and three assertions: a `toHaveClass` in `packages/pages/src/*.test.ts` rejected by `no-restricted-syntax`, a `screen.debug()` there rejected by `testing-library/no-debugging-utils`, and every `packages/*/package.json` carrying a `lint` script (`pnpm -r lint` silently skips one that does not). Seen red three ways: root config moved away → `LINT WALL CANNOT RUN: eslint produced no JSON report for packages/pages/src/__package_test_quality_fixture__.test.ts` (exit 1); `PACKAGE_TESTS` glob changed to `pkgs/…` → `LINT WALL BREACHED: packages lane: a toHaveClass assertion in a package test correctly rejected was NOT flagged by no-restricted-syntax (fired instead: nothing)` (exit 1); `lint` removed from `packages/pages/package.json` → ``LINT WALL BREACHED: packages with no lint script, which `pnpm -r lint` skips: pages`` (exit 1). Green restored each time. `scripts/__tests__/check-lint-wall.test.mjs` pins the count (36 → 39) and gained a case running the wall with an empty packages config (red when the seam is ignored: `actual: 0, expected: 1`); its "cannot start" case now excludes the packages lane's verdicts, since only the web config is broken there and the packages lane's rejections are genuine. Checks: `pnpm -r lint` (7 projects, exit 0), `node --test scripts/__tests__/check-lint-wall.test.mjs` (5/5), and one full `pnpm check`.
- **Decision (2026-09-25 overnight sweep):** one root `eslint.config.mjs` scoped to `packages/*/**`, with the ESLint toolchain as root devDependencies. Rejected: (a) an `eslint.config.mjs` per package — six copies, and under pnpm's strict layout each package would need the four devDependencies itself; (b) a `@tc/eslint-config` workspace package — a seventh package to hold what one file says; (c) extending `apps/web/eslint.config.mjs` to reach `../../packages` — its blocks are `src/**`-relative and full of UI walls that must not apply to packages, and ESLint 9 will not lint files outside the config's base path anyway.
- **Decision (2026-09-25 overnight sweep):** the packages' `no-unused-vars` adds `ignoreRestSiblings: true` to `apps/web`'s `argsIgnorePattern: "^_"`, which clears the 9 omit-a-key findings by configuration rather than 9 line-level disables. Rejected: (a) grandfathering them `KI-2026-09-02-b`-style — the idiom is not a defect and JavaScript has no other spelling for "this object minus one key", so a backlog of it would never shrink; (b) `varsIgnorePattern: "^_"` — broader, it would excuse any unused `_x`; (c) rewriting the tests to delete the key — a behaviour-adjacent change in contract tests for no gain. `apps/web` is left as it is; it hits the idiom only through arrow parameters, which its `argsIgnorePattern` already covers.
- **Decision (2026-09-25 overnight sweep):** root `lint` is `pnpm -r lint`, not `pnpm -r --if-present lint`, and the wall asserts every package has the script. `pnpm -r` already skips a package without it, so the assertion is what makes a seventh unlinted package fail rather than pass quietly — the species this entry was filed about.
