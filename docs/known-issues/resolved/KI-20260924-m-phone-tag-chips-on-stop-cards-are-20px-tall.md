### KI-2026-09-24-m — tag chips on phone stop cards are 20px tall, under SPEC §13.1's 44px floor — RESOLVED

- **Severity:** minor usability — they are tappable (they dim everything that is not that tag) but small.
- **Area:** the stop card's tag chips in `apps/web/src/components/board/ActivityCard.tsx`; `e2e/m26-phone-targets.spec.ts` (the floor check, which names its exceptions).
- **Symptom / What happens:** measured 2026-09-24 at 390px: chips are 43×20 and 60×20. They and the notebook breadcrumb (93×30) are the only phone controls under 32px apart from MapLibre's attribution links (known, accepted).
- **Why not fixed here:** a 44px chip changes the card's density; wants a design call (a larger hit area without a larger visual, or exempt them in the floor check with a reason).
- **Cross-reference:** SPEC §13.1, KI-2026-09-24-j (the tablet half of the same floor).
- **First noted:** 2026-09-24, mobile check.
- **Fix (2026-09-25):** the chip `<button>` is now the hit area and an inner `<span>` is the chip. Below `md` the button gets `min-h-11 -my-3`. `-my-3` gives back exactly the 24px that `min-h-11` adds, so the row lays out as if the button were still chip-sized. The target is 44px tall and the card and the chip look the same. It grows vertically only. Growing sideways would reach into the next chip, which is why `PHONE_TOUCH` (whose `min-w-11` is that sideways growth) is not reused. The span is `relative`, so when the chips wrap, a visible chip paints above the next row's invisible reach (a 6px overlap) and wins its own taps. `md:my-0 md:min-h-0` gives desktop back its old 20px button. `ActivityCard.tsx` only; the M18b focus ring and the hover dim moved onto the span with the look, and the unit test that reads the ring (`ActivityCard.test.tsx`, "rings the focused chip and only the focused chip") now reads the span.
- **Why the floor check never saw this:** two reasons, both fixed in `e2e/m26-phone-targets.spec.ts`. `mappedTrip` stops carry no tags, so no chip was rendered. And `countUnder` waits only for the header wordmark, which paints before the trip's stop cards: a probe right after it counted **0** activity cards on the Plan route. The spec now tags the first stop `meal` + `ticketed` via `UpdateActivity`, and the Plan route waits for `tag-chip-meal` before measuring. The chips were never in `ALLOWED`, so nothing had to be removed. They are enforced now because they are finally measured. The spec measures `getBoundingClientRect()` of the control itself, so a pseudo-element hit area would have stayed invisible to it. The real element box grows instead, and the box the spec measures is the box the browser hit-tests.
- **Proof:** with only the spec change, `pnpm test:e2e e2e/m26-phone-targets.spec.ts` failed in the same place on two runs: `+ "plan: \"Dim everything that is not meal\" is 20px"`, `+ "plan: \"Dim everything that is not ticketed\" is 20px"`. Putting the old `ActivityCard.tsx` back under the fixed spec made it fail again. With the fix: green on the dev lane, then `NEXT_PUBLIC_SENTRY_DSN='' pnpm build` + `CI=true pnpm test:e2e e2e/m26-phone-targets.spec.ts` (the two halves of `test:e2e:ci-like`), 3 passed. A throwaway geometry probe at 411px measured the chip button at 43×20 before and 43×44 after. The visible chip stayed 43×20 at the same y, and the stop card was 118px tall both times. At 1280px the button was 43×20 before and after. `elementFromPoint` at the chip's top, centre and bottom edges returned that chip, and the gap between two chips returned no chip. Unit: `vitest run -c vitest.unit.config.ts src/components/board/ActivityCard.test.tsx` 26/26. With the ring applied to every chip it failed (`expected 'inline-flex items-center rounded-sm p…' not to contain 'ring-brand'`), and after restoring the code it passed. `pnpm --filter web typecheck` clean; `eslint --max-warnings 0` on the three files, exit 0.
- **Decision (2026-09-25 overnight sweep):** a 44px hit area without a bigger chip, phone widths only, taken as the entry's first option. Rejected: exempting the chips in `ALLOWED`, because they are real controls on the main planning surface and an exemption would silence the floor instead of meeting it. Also rejected: a 44px-tall visible chip, which changes the card's density, the entry's own objection. Also rejected: a `::before`/`::after` hit area, which the floor check cannot see because it measures element boxes; passing it would have meant changing what the check measures. Also rejected: `PHONE_TOUCH` as is, because its `min-w-11` grows sideways into the next chip. The desktop keeps its 20px chips, the same `md` release as every other §13.1 rule. KI-2026-09-24-j (the tablet half) is untouched.
