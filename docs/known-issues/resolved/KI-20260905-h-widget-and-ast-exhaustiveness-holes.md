### KI-2026-09-05-h — `narrow` and `optionsFor` are not total over `FilterDimension`, and `serializePageNode` has no `never` default: two silent holes a new dimension or node type falls through — RESOLVED

- **Resolved 2026-09-24 (M14 T02).** `WidgetFilterValues` in `packages/pages/src/select.ts` is now a mapped type over `FILTER_VALUE_SCHEMAS`. Beside `narrow`, a `NARROWS: Record<FilterDimension, "days" | "contents" | "days and contents" | "refused">` table is what `contentNarrowed` is derived from, so a new dimension is a compile error at the one place a dimension gets meaning. `optionsFor` (`widgetBind.tsx`) names `tags` explicitly, returns no options for the four input types that have no select (`dates`, `person`, `days`, `trip`), and ends in a `never` default. `serializePageNode` and both of `ReadOnlyPageDoc`'s switches end in `const exhaustive: never = node`. No schema shape changed. **Proof:** a new `select.test.ts` sweep over `FilterDimension.options` is the runtime half. On HEAD, with a probe `currency` dimension added to the enum and to the three existing `Record`s, `@tc/pages` typecheck was clean in `select.ts` and the sweep failed: `AssertionError: currency was bound and selected every stop: expected 7 to be less than 7`. After the fix, the same probe fails to compile: `select.ts(109,7): error TS2741: Property 'currency' is missing in type … Record<"currency" | …>`. `pnpm redfirst` deleting the `kind` predicate turns the sweep red (`kind was bound and selected every stop`). Setting `NARROWS.kind` to `"days"` turns the existing tag/kind test red. For the switches, a probe deleted a case: a `field` member added to `WidgetInput`, `case "horizontalRule"` removed from `serializePageNode`, and `hardBreak`/`horizontalRule` removed from `ReadOnlyPageDoc`. Each typechecked clean on HEAD and fails after the fix with `TS2322 … is not assignable to type 'never'` (`widgetBind.tsx(201,13)`, `pageDoc.ts(592,13)`, `ReadOnlyPageDoc.tsx(71,13)`, `(160,13)`). **Checks:** `pnpm typecheck` across every package (a contracts file changed, so this was not narrowed), `pnpm --filter @tc/contracts test` (354/354), `pnpm --filter @tc/pages test` (187/187), eslint on the two web files, and web unit `PageScreen.test.tsx` + `NotebookScreen.test.tsx` (50/50). **Not done here:** `noImplicitReturns` repo-wide (its fallout is still unmeasured). `KNOWN_NODE_TYPES` is still a hand list. `serializePageInlineNode` and `serializePageListContentNode` are still two-way ternaries: a new member falls into the known-node arm and is serialised as itself rather than dropped. Unchecked `repeat` params belong to KI-2026-09-24-d, not here.

- **Severity:** correctness (latent — no case is missing today; both fire on the *next* addition, and neither fails a compile or a test)
- **Milestone:** **M14, gate box (recorded 2026-09-24, KI pass)** — M14's exit gate — *"Adding a filter dimension cannot be silently ignored"* cites this entry's reproduction. Listed in `docs/milestones/M14-rich-layer.md` § *Parked 2026-09-24*.
- **Area:** `packages/pages/src/select.ts:32-39` (`WidgetFilterValues` is a hand-written interface, not derived from `FILTER_VALUE_SCHEMAS`), `:124-137,159-164,197-198,223-226` (`narrow` names each dimension by hand); `packages/contracts/src/pages.ts:65,202-209`; `packages/pages/src/filters.ts:77,92,134`; `packages/contracts/src/pageDoc.ts:569-587` (`serializePageNode`, switch with no `default`), `:560-564`, `:118-131`; `tsconfig.base.json` sets `strict` and `noUncheckedIndexedAccess` but **not** `noImplicitReturns`
- **Symptom / What happens:**
  1. **A new filter dimension is accepted, stored, rendered as a control, and silently ignored ([F-B02](../../reviews/2026-09-05-overnight-review/findings/F-B02-narrow-is-not-total-over-filterdimension.md)).** Add `currency` to the enum: three `Record`s go red (good), the params schema accepts it, the chrome renders a control, `insertWidget` allows it — and `narrow` ignores it. `select.ts:106-108`'s own comment calls "a control that says narrowed while the widget renders wide" the worst of three answers. The same shape is why lighting up the already-declared `person` dimension is two uncaught edits.
  2. **A future `PageNode` member would be written as `null` and lock the page ([F-B03](../../reviews/2026-09-05-overnight-review/findings/F-B03-serializepagenode-has-no-exhaustive-default.md)).** A missing `case` compiles (confirmed by compiling a probe against the repo's tsconfig — `--noImplicitReturns` would flag it TS7030), returns `undefined`, is stored, becomes `null` in JSON, and fails `isNodeLike` on read → `unreadable` → locked page. No test can catch it: the round-trip generator only produces types *outside* `KNOWN_TYPES`, and the goldens are fixed. `BlockView.tsx:53-59` and `MacroView.tsx` already add `never` defaults with a note saying why; the contract file did not.
- **Why not fixed here:** found by a read-only review; no code was changed by it. Both fixes are small and mechanical (a mapped `WidgetFilterValues`, a `const handled: Record<FilterDimension, true>` beside `narrow`'s predicates, `default: { const exhaustive: never = node; … }` in both serialisers and `ReadOnlyPageDoc`'s two switches). Turning on `noImplicitReturns` repo-wide is the general answer and needs its fallout measured first.
