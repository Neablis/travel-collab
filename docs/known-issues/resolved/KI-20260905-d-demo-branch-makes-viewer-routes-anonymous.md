### KI-2026-09-05-d — the demo-trip branch makes every viewer-minimum route anonymous, and one of them is an unbounded database write — RESOLVED

- **Severity:** correctness (a security boundary: an unauthenticated, unquota'd, unbounded INSERT reachable by anyone with the URL)
- **Area:** `apps/web/src/server/access/trip-access.ts:80-85` (returns `{ userId: "demo-visitor", role: "viewer" }` when `isDemoTripId(tripId)`, **before** `auth()` at `:87`); `apps/web/src/app/api/saved-days/route.ts:23-26` → `savedDays.ts:157`; `apps/web/src/app/api/trips/[tripId]/pages/route.ts` → `pages-guard.ts:26` → `pages.ts:83`; `db/schema.ts:226` (`saved_days.owner_id` is free text, no `references()`); `handleAskRequest.ts:268-273` (the hand-written refusal that is the tell)
- **Symptom / What happens:** with no cookie at all, `GET /api/trips/00000000-0000-4000-8000-00000000d000` yields `days[].dayId`, and `POST /api/saved-days {"name":"x","tripId":"<demo>","dayId":"<id>"}` returns **201** and inserts a `saved_days` row with `owner_id = "demo-visitor"`. No quota applies (`consumeQuota` is wired only to `/ask` and `/geocode`) and there is no foreign key, so the rows are orphans forever — no user can list or delete them. The demo pages route also seeds default page rows for anonymous callers. ADR-031 intended four anonymous *reads* and states "the only database work in the whole demo is the clone" (`ADR-031:186`); the seam is generic, so every caller that asks for `viewer` inherits the anonymous answer.
- **Why not fixed here:** found by a read-only review (2026-09-05 overnight pass); no code was changed by it. The suggested fix is to make the demo answer **opt-in** per route rather than a property of the seam — the AI route already special-cases the demo trip by hand (KI-79), which is the evidence that the generic answer is the wrong default.
- **Cross-reference:** [F-A01](../../reviews/2026-09-05-overnight-review/findings/F-A01-demo-branch-makes-viewer-routes-anonymous.md) (severity MEDIUM, CONFIRMED end to end — reproduction, route table and fix scope); KI-79 (the same composition, closed on `/ask` only); ADR-031.
- **First noted:** 2026-09-05, overnight review stream A.

- **RESOLVED 2026-09-05** — the demo answer is **opt-in per route**, per this entry's own suggested fix. `requireTripAccess` takes `{ allowDemo }`, defaulting to **false**, and `guard()` threads it; the five ADR-031 reads plus `globals` (a pure in-memory read off `access.detail`) ask for it, and **`POST /api/saved-days` does not** — so an anonymous caller now gets the ordinary 401. `listPages` no longer seeds rows for the demo trip either: it folds the prebuilt pages in memory, which is what ADR-031:186's *"the only database work in the whole demo is the clone"* actually requires. A new route that forgets to ask is refused, which is the safe direction to forget in.
- **Proof:** two regression tests in `apps/web/src/server/demoTrip.int.test.ts`, both seen red against the old seam — `expected 201 to be 401` (the unbounded INSERT) and `expected 2 to be +0` (the pages route writing for an anonymous reader). The four pre-existing anonymous-read tests in the same file stayed green throughout, which is what proves the demo was not broken by closing the hole. Full integration lane: 40 files / 466 tests green.
- **Migration `0016_demo_visitor_orphans`** deletes the `saved_days` rows the hole already wrote (`owner_id = 'demo-visitor'`). **It does NOT add a foreign key**: `schema.ts:224` records the absence of one as an ADR-025 decision, on the same terms as `events.actor_id`, and overturning that is a separate argument with its own migration rather than a side effect of a cleanup. **Merging does not apply it** — dispatch `gh workflow run migrate-production.yml -f confirm=migrate` from `main`.
- **Left open deliberately:** KI-79's hand-written demo refusal in `handleAskRequest.ts:268-273` is now redundant — the seam refuses the demo by default — but removing it touches the AI route, which is M9's scope. Belt and braces until then.
- **Corrected 2026-09-06 after review of PR #147.** The first draft of this fix had two defects, both found by review and both real:
  * **CodeRabbit (Major):** folding the pages in memory used `newRow`, which mints a `randomUUID()` per call — so every list request handed out *different* page ids, and `GET /pages/[pageId]` (which reads through `getPage` → Postgres) **404'd every one of them**. Demo page ids are now derived from the page index (`…e000`, `…e001`) with a fixed epoch, and `getPage` resolves them from the same fold. Regression test asserts two list calls agree and that every listed id resolves 200; seen red against the random-id version.
  * **Copilot:** the demo branch sat *after* `listPages`' opening `db.select()`, so a demo request still queried Postgres — contradicting the invariant this entry cites — and any rows the old seeding left behind would have been returned ahead of the fold. The branch is now the first statement in the function.
- **Declined, with reason:** review also asked to delete `MacroNodeView.test.tsx`'s two-rule directive as a new bypass of the test-quality wall. It is the only regression guard for KI-2026-09-05-a, and it asserts **compiled CSS declarations** (`display: block`, `box-shadow`) rather than class spelling — which is the shape `AGENTS.md` actually objects to. Kept deliberately; recorded here rather than silently.
