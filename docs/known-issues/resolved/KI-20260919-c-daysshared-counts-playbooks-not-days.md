### KI-2026-09-19-c — `daysShared` counts playbooks, not days, and the name is what three surfaces rendered — RESOLVED

- **Severity:** correctness of a rendered number's MEANING (no wrong arithmetic; the count is right for what it counts, and the word beside it was wrong)
- **Area:** `apps/web/src/lib/playbooks.ts` (`PublicAuthor.daysShared`), `apps/web/src/server/playbooks.ts` (`publicAuthor`, fed by `publishedDayCount`), and its three renderers — `LeaderboardScreen.tsx`, `ProfileScreen.tsx`, `SharedDayScreen.tsx`
- **Symptom:** the field counts published `saved_days` ROWS. Until M23 a Playbook was exactly one day, so "days shared" and "playbooks shared" were the same number and the name was honest. M23 made a Playbook a SEQUENCE, and the two came apart: a three-day Playbook adds **one**. Walking the preview on PR #192 showed an author byline reading *"1 day shared"* directly beneath a Playbook the same page described as three days long.
- **What was fixed in #192:** the user-visible LABELS only — "playbook(s) shared", "Playbooks shared", "…newest of N playbooks". The rendered word now matches the computation.
- **What is still open, and why it was left:** the FIELD is still called `daysShared`, in the response shape, the server derivation and three components. Renaming it is mechanical but touches a wire shape plus its tests, and M23's PR already carried a migration, a contract change and four surfaces; widening it further was the worse trade. The next change that touches `PublicAuthor` should rename it (`playbooksShared`), along with `publishedDayCount`.
- **Why this is worth an entry rather than a shrug:** it is the `budgetPerPerson` defect class — a name asserting a semantic the computation does not have (`savedDayFacts.ts` carries that story). That one was caught by Mitchell reading the screen, and so was this one. A count whose noun is decided in three components is a count that will drift again.
- **Cross-reference:** ADR-048 (a Playbook is a sequence), `docs/milestones/M23-multi-day-playbooks.md` link 4.
- **First noted:** 2026-09-19, walking PR #192's preview.
- **Resolved 2026-09-25 (overnight sweep).** The field is now `PublicAuthor.playbooksShared`. The SQL alias it is read from is `playbooks_shared` (`leaderboard` and `publicAuthor`). The private `publishedDayCount` is now `publishedPlaybookCount`, and its docstring says a three-day Playbook counts as one. The rename covers `lib/playbooks.ts` (the schema, with the docstring rewritten), `server/playbooks.ts`, and the three renderers (`LeaderboardScreen`, `ProfileScreen`, `SharedDayScreen`), plus their unit tests and the `board`, `reports` and `saved-days/[savedDayId]` int tests. One correction to the Area line above: `publishedDayCount` does not feed `publicAuthor`. It feeds Discover's `sharedDayCount`. It was renamed anyway, as this entry asked, because it counts the same `saved_days` rows. **Wire check first:** `PublicAuthor` crosses only the app's internal routes (`/api/playbooks/board`, `/api/playbooks/profile/:userId`, the shared-day route). `server/public-api/discover.ts` imports `DiscoverDay`/`discoverPage` only, `packages/contracts/src` has no reference, and `docs/guidelines/using-the-api.md` does not mention it. So this is not a public `/v1` break, and no contracts CHANGELOG entry is owed. **Reproduction:** a new int test in `app/api/playbooks/board/route.int.test.ts`, *"counts a three-day Playbook as one playbook shared"*, saves and publishes one Playbook spanning three days. Under the old name it passed with `seen.days.map((d) => d.dayCount)` = `[3]` and `seen.author.daysShared` = `1`, which is the misnomer, reproduced. **Red-then-green:** with the test asserting `playbooksShared` and `toAuthor` put back to emit `daysShared`, the run fails with `ZodError: [{ "code": "invalid_type", "expected": "number", "received": "undefined", "path": ["author", "playbooksShared"] ... }]`, and `tsc` fails with `TS2353 ... 'daysShared' does not exist in type`. Restored, it is green. **Checks:** `pnpm --filter web typecheck` and `pnpm --filter web lint` clean. Web unit tests for the three screens pass 69/69. The int tests `board`, `reports` and `saved-days/**` pass 62/62 across 6 files.
- **Decision (2026-09-25 overnight sweep):** Discover's `sharedDayCount` was left alone, although it has the same defect class (it counts Playbooks). This entry names only `daysShared` and `publishedDayCount`, and `sharedDayCount` is a separate response field with its own tests. Renaming it here would widen the diff beyond the entry. Rejected alternatives: (a) keeping `publishedDayCount` because it does not feed `PublicAuthor` (rejected because the entry asked for the rename and the old name is equally wrong); (b) aliasing both keys on the wire during a transition (rejected because the only consumer is this app, which ships in the same deploy).
