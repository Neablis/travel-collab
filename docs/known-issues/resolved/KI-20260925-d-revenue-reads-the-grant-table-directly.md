### KI-2026-09-25-d — Billing's `underwaterReport` reads Entitlements' `entitlement_grants` table directly, a boundary crossing dependency-cruiser cannot see — RESOLVED

- **Severity:** cleanup — nothing misbehaves. It is the same boundary breach
  KI-2026-09-23-d closed for imports, by a route the wall does not watch.
- **Area:** `apps/web/src/server/billing/revenue.ts` (`underwaterReport`,
  counting accounts by grant source through `@/server/db/schema`),
  `apps/web/src/server/entitlements/admin.ts` (its only caller),
  ADR-047's 2026-09-25 amendment.
- **Symptom:** after 2026-09-25 Billing imports nothing of Entitlements but the
  plan catalog (`.dependency-cruiser.cjs`, `billing-imports-no-entitlements`),
  and `revenue.ts` takes trailing AI costs as an argument instead of reading
  Entitlements' ledger. It still queries `entitlement_grants` itself via the
  shared schema module, which the rule cannot see because the import is of
  `server/db/schema`, not of `server/entitlements/`.
- **Why not fixed here:** found by KI-2026-09-23-d's fixer (overnight sweep,
  2026-09-25), outside that entry's scope. Intended fix: the same reversal the
  ledger got — `admin.ts` reads the grant holders and passes them in.
- **Cross-reference:** `resolved/KI-20260923-d-billing-imports-entitlements-against-adr-047.md`, ADR-047.
- **First noted:** 2026-09-25, overnight KI sweep.
- **Resolved 2026-09-25 (overnight sweep).** The grant holders now go the same way as the ledger did under KI-2026-09-23-d. `entitlements/grants.ts` gains `activeGrantHolders(now)`, which returns `{ source, userId }` for every grant active at `now` and uses the module's own `activeAt` predicate. `underwaterReport` in `billing/revenue.ts` takes those holders as a `grants` argument (`GrantHolding`, declared in Billing). It no longer imports `entitlementGrants` from `@/server/db/schema`. `entitlements/admin.ts` reads the holders once in `adminOverview` and passes them in. `grantSourcePanel` now calls the same function instead of repeating the raw-SQL read. ADR-047's 2026-09-25 amendment gets a bullet saying so. **Reproduction:** `grep -rn entitlementGrants src/server/billing` (test files excluded) printed `revenue.ts:28: import { entitlementGrants, users } from "@/server/db/schema";` and the query at `:294-297`. **Guard:** `pnpm arch` is not enough here. dependency-cruiser sees the import of `db/schema`, which every module may use, not the table symbol. So a new unit sweep, `billing/storeBoundary.test.ts`, checks Billing's comment-stripped non-test source for `entitlementGrants`, `entitlement_grants`, `aiUsage` or `ai_usage`. It uses the `sourceSweep` helper that `soleWriter.test.ts` uses. Written before the fix, it failed with `expected [ 'revenue.ts: entitlementGrants' ] to deeply equal []`. After the fix it passes. **Red-then-green on behaviour:** with `underwaterReport` made to ignore `grants`, 2 of `revenue.int.test.ts`'s 11 tests went red (`puts the comped account and the paying one in different buckets`: `expected undefined to be 1`; `reports the grant-funded half as a count…`: `expected undefined to be defined`). Restored, they pass. **Checks:** `pnpm --filter web typecheck` clean. eslint on the five changed files clean. `pnpm arch`: 0 errors, 9 warnings, unchanged. Billing + entitlements unit files: 18 files / 151 tests. Billing + entitlements int files: 12 files / 108 tests. `revenue.int.test.ts` + `admin.int.test.ts`: 27/27.
- **Decision (2026-09-25 overnight sweep):** the guard is a source sweep of table names, not a dependency-cruiser rule. Rejected: (a) a dep-cruiser rule, which cannot see symbol use, only the `db/schema` import every module shares. (b) An ESLint `no-restricted-imports` `importNames` rule on `@/server/db/schema` for `src/server/billing/**`. It would miss raw SQL naming the table, and flat config replaces a rule's options per block, so the gateway wall would have to be re-asserted for that directory (the hazard `eslint.config.mjs` documents twice). The sweep also covers `aiUsage`, because the ledger inversion KI-2026-09-23-d made had the same unguarded back door. The holders are passed as rows, not as pre-counted per-source sets. That keeps the counting and the `paying`/`grantFunded` disjointness logic in Billing, where the tests pin it.
- **Correction (2026-09-25, PR #234 review):** "reads the holders once in `adminOverview`" was not true. `grantSourcePanel(now)` still called `activeGrantHolders` itself, so the overview read them twice. It also read the trailing ledger six times: `costByPlan`, `planPanel`'s revenue half, `grantSourcePanel`, `adminAccounts`, `adminTopSpenders` (which is `costPerAccount(...).slice`) and the overview's own `trailing`. `adminOverview` now reads each once and hands the rows to every panel. The new `entitlements/adminOverview.int.test.ts` wraps the real functions and pins one read of each. Before the change it failed with `expected [ [ 'costPerAccount' ], …(5) ] to deeply equal [ [ 'costPerAccount' ] ]`.
