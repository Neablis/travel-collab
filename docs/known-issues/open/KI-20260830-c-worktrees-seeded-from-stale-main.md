### KI-2026-08-30-c — Agent worktrees are seeded from a stale `main`, so a subagent can read repo files that are commits out of date — including its own binding contract
- **Severity:** reliability (of agent work, not of the product) — it does not corrupt anything, but it makes a subagent draw confident conclusions from a checkout that is not the one it was told to work on
- **Area:** the harness's worktree creation (`.claude/worktrees/agent-*`), and this repo's assumption in `AGENTS.md` and `.claude/agents/*` that a dispatched subagent can read `.claude/protocol/CONTRACT.md` and `ADAPTER.md`.
- **What happened, measured on the 2026-08-30 sweep:** four `ki-fixer` subagents were dispatched with `isolation: worktree`. Every worktree was created at **`419d75a`**, the local `main`/`origin/main` ref at session start — while the branch they were told to work from was at `7de5d56` plus three commits. `419d75a` predates **`63f83ff`** (PR #75), the commit that *added* `.claude/protocol/`. So in each fresh worktree that directory genuinely did not exist.
- **The consequence is a wrong claim about the repo, not just a stale read.** Two of the four agents independently reported `.claude/protocol/` as missing. One went further and concluded, in its report: *"the subagent contract is unreadable and whatever test guards it cannot be running."* Both statements are false of the repo — the directory is tracked, un-ignored at `.gitignore:29`, and its portability test runs and passes. Two of four units is not a fluke, and the failure mode is the expensive kind: a confident, specific, wrong finding that a reader has no obvious reason to doubt.
- **Why the local ref was stale in the first place:** `origin/main` in this container pointed at `419d75a` until an explicit `git fetch origin main` moved it to `7de5d56`. Nothing in the session had fetched since the container was provisioned, and the worktree pool was seeded from that ref rather than from the branch under work.
- **What makes it hard to spot:** both agents *did* correctly branch off the commit they were told to (`920d53f`), so their commits are sound and their fixes are correct — verified. Only the observations they made **before** switching are stale. A report can therefore be right about its own change and wrong about the repo in the same breath, which is exactly the combination that survives review.
- **Fix path, in preference order:** (a) create worktrees from the branch under work rather than from a cached ref, or fetch before seeding the pool; (b) failing that, have `ki-fixer` and `phase-implementer` verify their base with `git rev-parse HEAD` and check out the intended commit **before** reading any repo file — the contract read currently happens first; (c) at minimum, treat "a file `AGENTS.md` says is binding appears to be missing" as a signal to check `git log` for when it was added, not as a finding.
- **Why not fixed here:** worktree creation is harness behaviour, not repo code, so (a) is not in this repo's gift. (b) is a real change to two agent definitions and wants its own reviewed step rather than being appended to a four-issue sweep branch.
- **Cross-reference:** KI-89 (resolved — its own report flagged a concurrent writer on the shared database, a sibling isolation gap), `.claude/protocol/ADAPTER.md`'s exclusive-resources table, `AGENTS.md`'s worktree rule.
- **First noted:** 2026-08-30, reconciling two subagent reports that disagreed with the repo.
- **Re-verified 2026-09-25 (overnight sweep):** still true, observed first-hand by a validator in its own `isolation: worktree` checkout. Before its ff-merge, `git log -1` in `.claude/worktrees/agent-a1b01248900c45006` showed **`cdb3582`** (#231), which is `origin/main`, while the base it was dispatched to use was `20e7181` on `claude/ki-cleanup-overnight-en459g`. So the worktree was again seeded from the main ref, not the branch under work. This time the gap was one docs-only commit, because `origin/main` had been fetched recently. The local `main` ref, a second candidate seed, sat at `57922bd` (#205), several PRs behind. Fix (b) is still not done: `grep -n "rev-parse\|merge --ff-only" .claude/agents/*.md` finds nothing, so neither `ki-fixer` nor `phase-implementer` checks its base before reading. In practice the orchestrator's brief now opens with `git log -1` plus `git merge --ff-only <base>`, and that caught it here.
