### KI-2026-09-12-f — `ProposalBuffer.collected()` copies the array but not the records, so the guarantee its own comment states is only half true

- **Severity:** correctness — latent. No caller is known to mutate a record it reads back; this is the same defect class as `KI-2026-09-11-d`, in the file that entry cited as the *correct* example.
- **Area:** `apps/web/src/server/assistant/deps.ts:104` (`collected: () => [...intents]`) and `:106` (`inserts: () => [...inserts]`), against the comment at `:74` — *"Handing back a COPY from `collected()`/`inserts()` rather than the live array"*.
- **What is wrong:** `RawToolIntent` (`apps/web/src/server/ai/batchResolver.ts:40-45`) is a mutable interface whose `args` is itself a mutable `Record<string, unknown>`. `[...intents]` copies the array and shares every element, so a caller that mutates a record it read back — or anything inside `args` — rewrites what the turn collected. The comment promises protection the spread does not provide.
- **How it came to light:** CodeRabbit made exactly this finding against `newTurnMeter().toolCalls()` on PR #165, where the first fix for `KI-2026-09-11-d` was also `[...tools]`. That was fixed to `tools.map((tool) => ({ ...tool }))` with a test that mutates a returned record. Checking the sibling that `KI-2026-09-11-d` held up as the model showed it has the same hole — so that entry's framing (*"its sibling copies and says copying is the point"*) is accurate about the intent and wrong about the effect.
- **Why not fixed there:** `toolCalls()` returns flat records, so one spread per element closes it. `RawToolIntent.args` is an open-ended nested object, so the equivalent fix has to answer *how deep* — a per-element spread still shares `args`, and `structuredClone` on every read has a cost nobody has measured on this path. That is a judgement call rather than a one-line change, and `deps.ts` sits in `server/assistant/` which M9's grounding phase is actively editing.
- **Scope:** decide the depth (per-element spread plus a cloned `args`, or `structuredClone`, or freezing on collect instead of copying on read), apply it to `collected()` and `inserts()`, and add the mutate-a-returned-record test that `ledger.test.ts` now has.
- **Cross-reference:** `KI-2026-09-11-d` (resolved, the same class in `ledger.ts`); PR #165's CodeRabbit thread on `ledger.ts:211`.
- **First noted:** 2026-09-12, while addressing CodeRabbit's review of PR #165.
