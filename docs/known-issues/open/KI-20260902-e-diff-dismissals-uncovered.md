### KI-2026-09-02-e — `diffTripStates` step 7 (conflict dismissals) has no test coverage at all

- **Severity:** correctness risk, unproven. The code looks right on reading; nothing proves it, and it sits on the time-travel path.
- **Area:** `packages/domain/src/trip/diff.ts` lines 171-181 — the two loops that reconcile `dismissedConflictIds` between working and target state, emitting `ConflictUndismissed` and `ConflictDismissed`.
- **How it was found:** the first real run of `pnpm mutate` (`scripts/mutate.mjs`, added the same day). `pnpm mutate packages/domain/src/trip/diff.ts` — 29 seconds, 78.29% total score, **114 killed, 25 survived, 8 no-coverage**. All eight no-coverage mutants are in step 7. Stryker deleted both loop bodies, inverted both conditions and blanked both event types, and **no test ran the lines at all**.
- **Why it matters:** `diffTripStates` is how time travel works — restoring an earlier state is expressed as the events that get you there. If step 7 is wrong, dismissing a conflict and then undoing past it either re-raises a conflict the user dismissed or silently keeps one dismissed that should be back. Neither fails loudly. `diff.ts` is also KI-1's home, which is the reason the test-overhaul plan named it as a mutation target in the first place.
- **The 25 survived mutants elsewhere in the file are a separate question** and are NOT all defects — a surviving mutant can mean a line nothing needs. They are worth a read, and they are not what this entry is about. The eight with no coverage are unambiguous: no test executes that code.
- **Fix path:** two unit tests in `packages/domain/test/diff.test.ts` — a working state that dismissed a conflict against a target that had not (expect `ConflictUndismissed`), and the reverse (expect `ConflictDismissed`). Then re-run `pnpm mutate packages/domain/src/trip/diff.ts` and confirm the no-coverage count is zero. Small, self-contained, good ki-sweep material.
- **Why not fixed here:** found while proving the instrument works, in a PR that adds the instrument. Fixing it inside that PR would have meant the tool's first finding never got written down as a finding — and the measurement above is the thing a future session needs in order to re-measure without re-deciding, which is what the test-overhaul plan asked for.
