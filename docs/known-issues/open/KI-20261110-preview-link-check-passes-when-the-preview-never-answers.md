### KI-2026-11-10 — preview-link-check concludes success when the preview never answers

- **Severity:** reliability (a missing preview reads as a green check, so nobody is told to look).
- **Area:** `.github/workflows/preview-link-check.yml` (the `wait` step, lines 55-66), `scripts/check-preview-links.mjs`.
- **Symptom / What happens:** when `$PREVIEW_URL/api/health` never reports the head sha, the `wait` step falls through its 90-try loop (lines 58-62), writes a `::warning::` and a step summary (lines 63-65), sets `ready=false` (line 66) and **ends without `exit 1`**, so the step succeeds. The link step is skipped by `if: steps.wait.outputs.ready == 'true'` (line 68), and the job concludes `success`. Seen on PR 718: https://718.preview.caesura.today answered with Traefik's default certificate (`ERR_CERT_AUTHORITY_INVALID`, no router for the host). Run 42738117800 on `4254305` logged "/api/health did not report version … in 15 minutes (last: no answer); sea links not checked" and its conclusion was `success`. The comment at lines 52-54 makes this deliberate (a preview that never appears is "a warning, not a red check"), but the cost is that **a PR with no preview at all shows the same green as one whose sea links were all checked**.
- **Why not fixed here:** M60 part 0 is prose-only (`docs/**`, `.claude/**`). The workflow is outside it, and changing which outcome is red is a decision about PRs that legitimately have no preview. Intended fix: keep the check non-required, but end the `wait` step with `exit 1` when the PR targets `main` and is ready (a ready PR on `main` is meant to have a preview), or add a final step that fails when `ready` is not `true`.
- **Cross-reference:** M51 ("The links stay real"), M60 close, `docs/guidelines/stacked-prs.md` (retargeted top PR), `.claude/skills/close-a-milestone/SKILL.md`.
- **First noted:** 2026-11-10, M60 close. Likely, not proven, cause of PR 718's missing preview: Coolify creates a preview when a PR opens against `main`, and PR 718 opened against the part-4 branch and was retargeted to `main` later.
