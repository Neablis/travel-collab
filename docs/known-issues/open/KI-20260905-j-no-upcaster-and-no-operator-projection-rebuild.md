### KI-2026-09-05-j — there is no event upcaster and no operator path to rebuild projections, so a non-additive schema change has nowhere to land

- **Severity:** correctness risk (nothing is broken today; this is the machinery three guidelines describe as existing, which does not)
- **Area:** `packages/contracts/src/trip.ts:206-222` (`TripEvent = z.discriminatedUnion("type", …)`, every member `version: z.literal(1)`), `activity.ts:169-193`, `history.ts:44-58`; the five parse sites (`packages/domain/src/trip/{project,detail,history}.ts`, `apps/web/src/server/projections.ts:18`); `apps/web/src/server/projections.ts:66-80` (`rebuildProjections` — callers are tests only); no rebuild script in `apps/web/scripts/`, no workflow
- **Symptom / What happens:**
  1. **No upcaster exists, and the prescribed procedure is impossible as written ([F-C01](../../reviews/2026-09-05-overnight-review/findings/F-C01-no-event-upcaster-layer.md)).** ADR-003:47-48 promised "versioned events and upcasters so old logs replay", and `building-the-parts.md:23-25`, `quality-enforcement.md:11` and `connecting-the-parts.md:37` describe the procedure as if it exists. Only the `version` *literal* exists, emitted at 34 sites; no `upcast` symbol exists anywhere; and `TripEvent` discriminates on `type` alone, so Zod 3 cannot hold two versions of one `type` in the union. **What happens today when a stored row does not parse:** it is never skipped — every command, history read, point-in-time read and pinned share throws a `ZodError` → 500, and `rebuildProjections` aborts on the first bad row of *any* trip with an error carrying neither `streamId` nor `seq`.
  2. **No operator can rebuild ([F-C02](../../reviews/2026-09-05-overnight-review/findings/F-C02-no-operator-projection-rebuild.md)).** AGENTS.md invariant 2 says projections are disposable and CI proves it, but no CLI, route or workflow lets an operator rebuild after a reducer or projection-shape change. The one function loads every event into memory and is all-or-nothing. Suggested fix: a per-stream `rebuild-projections.mjs` that logs and skips the streams it cannot parse, plus a `workflow_dispatch` beside `migrate-production.yml`; keep the all-in-one function for the golden test.
  3. **A related coverage nit ([F-C06](../../reviews/2026-09-05-overnight-review/findings/F-C06-golden-rebuild-misses-activityupdated.md)):** none of the five rebuild-comparing integration suites ever issues `UpdateActivity`, so a stored `ActivityUpdated` payload's Postgres jsonb round-trip is unproven. Domain semantics *are* covered elsewhere. One added command in `commands.int.test.ts`'s rebuild-equality case closes it.
- **Why not fixed here:** found by a read-only review; no code was changed by it. Stream C's verdict is that **additive** change is solid — every schema change so far was additive-with-default, ~1 day of consumer work and zero migrations (the proven M18 path). It is the **non-additive** pivot (a money model, absolute instants) that is blocked on these two plus KI-2026-09-05-m. The review's recommendation: write the ADR before the pivot, not during.
