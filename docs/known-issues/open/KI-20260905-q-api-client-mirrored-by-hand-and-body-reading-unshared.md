### KI-2026-09-05-q — the "typed API client" is 35 hand-mirrored wrappers plus a second client plus three raw fetches, and five routes 500 on malformed JSON because body reading has no shared helper

- **Severity:** correctness (the five 500s are a client error reported as a server fault, and each one is a Sentry event) + cleanup (the mirroring)
- **Area:** `apps/web/src/lib/apiClient.ts` (999 lines, 35 `fetch(` calls against 37 `route.ts` files, **35 byte-identical** `catch` blocks), `lib/pagesClient.ts` (a second client with its own helpers and its own mirrored totality suite), raw `fetch` at `app/(app)/page.tsx:109`, `components/board/LocationInput.tsx:27`, `app/sentry-example-page/page.tsx:81`; bare `safeParse(await request.json())` at `api/trips/route.ts:43`, `trips/[tripId]/pages/route.ts:23`, `pages/[pageId]/route.ts:20`, `commands/route.ts:18`, `commands/batch/route.ts:21`; the guarded `.catch(() => null)` form at `invites/route.ts:14`, `saved-days/route.ts:17`, `account/preferences/route.ts:72`; `apps/web/src/mocks/handlers.ts:15-16`
- **Symptom / What happens:**
  1. **[F-E04](../../reviews/2026-09-05-overnight-review/findings/F-E04-five-routes-500-on-malformed-json.md) — five routes 500 on malformed JSON while three return 400.** `Request.json()` rejects on invalid JSON; in the bare form the rejection escapes the handler and Next returns 500 for a client error, and Sentry records it as a server fault. Zod failures *do* return 400 in all five, so the inconsistency is purely the body read. The access half of the route preamble is well centralised (`requireTripAccess`); body reading is not, which is why the split is 5 bare vs 3 guarded. The correct in-repo pattern already exists at `handleAskRequest.ts:297-302`.
  2. **[F-F03](../../reviews/2026-09-05-overnight-review/findings/F-F03-ask-handlers-duplicate-body-ritual.md) — the two AI handlers duplicate that ritual verbatim** (`handleAskRequest.ts:296-305` and `:846-855`, byte-identical), and the demo refusal too (`:268-273`, `:831-836`). It is the best-tested instance of the helper F-E04 wants. **Do these two as one change.**
  3. **[F-E03](../../reviews/2026-09-05-overnight-review/findings/F-E03-api-client-is-35-hand-mirrored-wrappers.md) — every new route costs a hand-written wrapper, a hand-written mock and a hand-copied try/catch.** The totality invariant ("a client helper never rejects") is guarded *per module*: `apiClient.test.ts:229-261` enumerates only its own exports — it cannot see `pagesClient.ts` (which had to grow its own copy of the suite after a reject bug on 2026-09-03) or any raw `fetch`, and nothing lints `fetch` outside the client. Two guideline sentences describe mock generation that does not exist.
- **Why not fixed here:** found by a read-only review; no code was changed by it.
- **Suggested fix:** a `readBody(request, schema)` in `apps/web/src/server/` returning the same `"error" in x` shape as `requireTripAccess`, used by all eight routes and both AI handlers; a `no-restricted-syntax` lint on `fetch` outside the two client modules (80% of the value at 2% of the cost); then collapse both clients onto one `request<T>(path, init, parse)` core so totality is structural — one try/catch, not 35.
