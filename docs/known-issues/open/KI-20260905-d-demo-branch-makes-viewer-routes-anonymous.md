### KI-2026-09-05-d — the demo-trip branch makes every viewer-minimum route anonymous, and one of them is an unbounded database write

- **Severity:** correctness (a security boundary: an unauthenticated, unquota'd, unbounded INSERT reachable by anyone with the URL)
- **Area:** `apps/web/src/server/access/trip-access.ts:80-85` (returns `{ userId: "demo-visitor", role: "viewer" }` when `isDemoTripId(tripId)`, **before** `auth()` at `:87`); `apps/web/src/app/api/saved-days/route.ts:23-26` → `savedDays.ts:157`; `apps/web/src/app/api/trips/[tripId]/pages/route.ts` → `pages-guard.ts:26` → `pages.ts:83`; `db/schema.ts:226` (`saved_days.owner_id` is free text, no `references()`); `handleAskRequest.ts:268-273` (the hand-written refusal that is the tell)
- **Symptom / What happens:** with no cookie at all, `GET /api/trips/00000000-0000-4000-8000-00000000d000` yields `days[].dayId`, and `POST /api/saved-days {"name":"x","tripId":"<demo>","dayId":"<id>"}` returns **201** and inserts a `saved_days` row with `owner_id = "demo-visitor"`. No quota applies (`consumeQuota` is wired only to `/ask` and `/geocode`) and there is no foreign key, so the rows are orphans forever — no user can list or delete them. The demo pages route also seeds default page rows for anonymous callers. ADR-031 intended four anonymous *reads* and states "the only database work in the whole demo is the clone" (`ADR-031:186`); the seam is generic, so every caller that asks for `viewer` inherits the anonymous answer.
- **Why not fixed here:** found by a read-only review (2026-09-05 overnight pass); no code was changed by it. The suggested fix is to make the demo answer **opt-in** per route rather than a property of the seam — the AI route already special-cases the demo trip by hand (KI-79), which is the evidence that the generic answer is the wrong default.
