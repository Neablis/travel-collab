### KI-2026-09-05-w — nine small duplications and dead exports: a second statement of the tool sets, two pass-throughs, two command executors, a redundant wall, a dead gate, four `Queryable`s, a dead menu, and a misplaced module

- **Severity:** cleanup — nine LOW findings, all CONFIRMED, none with any user impact. Bundled; strike a line as it lands. Total is roughly 150 lines removed across 9 independent edits.
- **Area:** see each finding below.
- **Symptom / What happens:**
  1. **[F-F02](../../reviews/2026-09-05-overnight-review/findings/F-F02-offeredtoolnamesfor-is-a-second-statement-of-tool-sets.md)** — `offeredToolNamesFor`/`AskToolSet` (`handleAskRequest.ts:92-124`) is a second, production-unused statement of which tools a turn gets; the runtime builds `tools` from the three builders. `route.int.test.ts:337` asserts it against a restatement of its own implementation, so the test cannot fail for any reason the implementation does not share. ~35 → ~5 lines.
  2. **[F-F04](../../reviews/2026-09-05-overnight-review/findings/F-F04-two-single-caller-passthroughs-in-write-path.md)** — `buildWriteTools()` is `return buildPlanningTools()` (and `:45` already calls the latter directly, contradicting the "named door" justification), and `flushPlanningBatch(_tripId, calls, actorId)` passes through with `_tripId` unused. ~20 → ~2 lines; add a note to ADR-033 decision 5, which names `flushPlanningBatch` as surviving — the intent was the pipeline, not the wrapper.
  3. **[F-F06](../../reviews/2026-09-05-overnight-review/findings/F-F06-two-command-executors-share-five-steps.md)** — the two executors in `commands.ts` spell five of their seven steps twice (load+fold, members+forbidden, append+conflict differing only in `origin`, project), and the `TripHistory` literal is built twice. The invariant-1 sequence is written twice, so a change to the append/projection tail must be made in both. ~32 lines.
  4. **[F-F07](../../reviews/2026-09-05-overnight-review/findings/F-F07-sleep-wall-redundant-with-eslint.md)** — `scripts/check-sleep-wall.mjs` duplicates `playwright/no-wait-for-timeout`, which has been at **error** over `e2e/**` since 2026-09-02, across a directory with zero `waitForTimeout` calls. Two exemption spellings for one rule, plus an extra Node process per `pnpm lint`. (The finding's first draft claimed it had no test; it does — `scripts/__tests__/check-sleep-wall.test.mjs` — and the verifier narrowed the finding to "redundant".) Deleting it means adding a `lintFixture` case to `check-lint-wall.mjs` proving the ESLint rule fires, and fixing five now-inverted references.
  5. **[F-F08](../../reviews/2026-09-05-overnight-review/findings/F-F08-checkadmission-dead-and-header-lies.md)** — `checkAdmission` has no production caller (only its own tests), and `admission.ts:13-17` describes the code being "asked twice — advisorily by the `/signup` form", a path that was never wired. Not a hole — `redeemAdmission` is the real gate and is wired and tested including its concurrency case — but a security module's header describing a check that does not exist is worth deleting rather than leaving to be believed.
  6. **[F-F09](../../reviews/2026-09-05-overnight-review/findings/F-F09-small-duplicates-in-server-ai.md)** — `usageOf` is byte-identical in `askAnalytics.ts` and `askIntent.ts` (which already imports from the former), and `modelIdOf` exists twice. ~12 lines. (The draft's "three truncators" clause was **dropped** — they differ in behaviour.)
  7. **[F-F10](../../reviews/2026-09-05-overnight-review/findings/F-F10-queryable-declared-four-times.md)** — the identical `Queryable` type is declared in four modules, one with an apology, because `db/client.ts` exports only `db` and `Db`. ~9 lines.
  8. **[F-F11](../../reviews/2026-09-05-overnight-review/findings/F-F11-accountmenufromsession-dead-and-comments-stale.md)** — `AccountMenuFromSession` has no production caller, and `AppHeader.tsx:11-14` plus two test comments name it as what `AppHeader` renders, which is `HeaderSessionChrome`. ~8 lines and three comments.
  9. **[F-F12](../../reviews/2026-09-05-overnight-review/findings/F-F12-geocodenamematch-lives-in-ai-but-only-seed-uses-it.md)** — `server/ai/geocodeNameMatch.ts` (220 lines + 266 of tests) is imported only by `scripts/geocode-japan-seed.mts`, so anyone auditing `server/ai/**` reads 486 lines no request touches. **Do not move it before resolving KI-15's F-G02 note** — the answer there is that live enrichment *should* be calling it, in which case it stays and gains a caller.
