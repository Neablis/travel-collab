## M20 — six phases

Each phase is one branch and one PR. **Scoped code runs the `minimal-check-subset`
skill's output, not `pnpm check`** (CLAUDE.md rule 4); the full suite is a
final-review cost paid once when the branch leaves draft.

**On every one of these PRs: resolve review threads by hand as each fix lands.**
`docs/guidelines/working-a-review.md` was corrected on 2026-09-13 — CodeRabbit's
threads self-resolve only where reviews re-run automatically, and they do not in
this repository (*"fewer than 10 stars"*), so its threads behave like Copilot's
and stay open forever. Measured on PR #170: fourteen findings, all fixed and
pushed, all fourteen still open hours later. Its Merge Risk verdict is stamped
at one commit and never recomputed, so a stale verdict needs a PR comment
mapping each claim to the commit that answered it — six phases of this is where
that cost compounds.

### Phase 1 — the vocabulary and the three plans (link 1)

`packages/contracts` gets the entitlement enum; a new committed plan-version
file gets the three launch plans as `v1`, typed against that enum.

- **No prices.** M20 publishes versions that are free by construction; link 2
  of M21 adds `price_minor`, `currency` and `stripe_price_id` to the same
  entries. A price string in this diff means the split failed.
- **No plan is defined in terms of another.** `premium` enumerates its own
  entitlements. The test that fails on a spread, an extend or any read of
  display order is written **in this phase**, not later — it is the box the
  design most easily loses and losing it is a one-way door.
- Contracts changelog entry: `docs/contracts/CHANGELOG.md`.

Closes: *no plan is defined in terms of another*; *publishing a version whose
entitlement list contains a string outside the enum cannot compile*.

### Phase 2 — the migration, the grants, the resolver (links 2, 3)

The migration (**`0019`** as of 2026-09-13 — confirm per preflight item 4):
`entitlement_grants`, plus `plan` and `is_admin` on `users`. No foreign keys, per the schema's standing convention. Then
`entitlementsFor(userId)` — the file for what a plan is, the table for who
holds what, unioned, per request (ADR-045 rules 1 and 2).

- **The founder backfill is part of this migration**: every account existing at
  migration time gets a permanent `founder` grant and loses no capability it
  had the day before.
- **A grant pins the version it was granted at** (ADR-045 rule 3): an
  unresolvable version reference fails loudly, never silently to the newest.
- Wire the resolver into `permitEverything`'s place at
  `modelSelection.ts:213`'s default — a change *inside* the function, not a
  signature change, exactly as the seam's comment requires.
- **The trial grant is issued here too** — `source: "trial"`, `plus`, one week,
  `expires_at` set when the `users` row is created. M20's own text says it
  *"needs no ninth link — it is link 2's table and link 3's resolver with a
  different `source`"*, so it belongs in this phase rather than with the
  referral loop.
- **The trial is one time ever per account, and that is a retention rule before
  it is a feature.** Eligibility asks *"has this account ever held a trial
  grant"*, reading expired and revoked rows alike. **Nothing may delete or
  sweep `entitlement_grants`.** Write the test that fails when an expired grant
  is removed **in this phase**, while the table is new and the temptation to
  add a cleanup job has not arrived yet.
- **PR body must call out the production dispatch.** An undispatched migration
  is schema drift.

Closes: the grant/expiry boxes; *a grant pins the version*; *an account on `v1`
is unaffected by `v2`*; the founder-grant box; the trial box (both halves — the
week, and the one-time rule); the migration box.

### Phase 3 — the AI gate and tiered ceilings (links 4, 5)

Fill the resolver in behind the seam; **403 → 402** with the wire code
`ai-not-entitled`, and a client that offers an upgrade path rather than
rendering a permission error. Populate `EntitlementCeilings` from the pinned
version. **Carry the `/ask` step-metering fix here** — `handleAskRequest`
charges `aiQuotas()` but never `aiStepQuotas()`/`settleAiSteps`, so only one of
the two AI endpoints bounds its round-trips.

- **Upgrading a tier must not reset a quota counter.** The bucket name is
  tier-independent; the ceiling is not. Naming the trap is not evidence it was
  avoided — assert it.
- **Per-user ceilings come from the pinned version; the global ceiling comes
  from the environment.** Republishing a plan does not move a global ceiling.
- Contracts changelog: the 403→402 change is a **breaking wire change**.

Closes: the 402 box; the two-ceiling box; the quota-reset box; the
`aiStepQuotas()` box.

### Phase 4 — the collaboration gate, applied on read (link 6)

Inviting requires the entitlement. On lapse, granted memberships **cap at
`viewer` on read** in `effectiveMembers` — never written to
`trip_memberships.role`, so resubscribing restores every collaborator with zero
writes.

- The refusal names the **tier**, not a permission.
- ADR-045 rule 5 is live here: the gate lives in Access & Membership, reads a
  boolean from Entitlements, and Entitlements never imports a trip type. This
  is the phase where that boundary is most likely to be violated.
- Trip planning stays **entirely free** — a test proves it, and that test is
  this milestone's most important negative.

Closes: the three-collaborator lapse box (byte-identical rows, restore with
zero writes); the free-owner-cannot-invite box; the trip-planning-is-free box.

### Phase 5 — the cost ledger (link 9)

One `ai_usage` row per AI request, shaped as ADR-043's `TurnLedger` already
emits — **tokens and model ids, never dollars**. Dollars are derived at read
time from a dated rate table.

- **`Money` must not appear anywhere in this path.** A $0.0006 request rounds
  to zero in `amountMinor`; that is the KI-1 / KI-14 / `budgetPerPerson` defect
  class on its third recurrence, and a test fails if either appears.
- **A request that fails partway still writes a row** — the round-trips were
  paid for. Assert the failure path writes.
- No question text, no trip content.
- **Before Phase 6**, because the console reports cost per account from it.

Closes: the one-row-per-request box; the no-`Money` box; the re-pricing-history
box; the `ai_usage` carries no content box.

### Phase 6 — the operator console and the referral loop (links 7, 8)

A route group behind `users.is_admin`, **read-only over plans** (versions are a
committed file; the console shows what is live, it does not edit it). Accounts
per plan, accounts per active grant source, cost per account over a trailing
window, top spenders — each **walked**, not just queried. Then the hand-grant
path, self-serve invite codes and the referral reward.

- **The MRR / ARPU / margin strip is M21's, not this milestone's.** M20 ships
  the console without it. Building it here is the split failing in the
  direction nobody checks.
- A referral earns one month of the tier the referrer **holds** — a `free` or
  trial-only referrer earns nothing, a self-redeemed code earns nothing, and
  the per-account cap holds under repeated redemption.
- A non-admin reaches no admin route **and no admin endpoint**, checked
  server-side; a test proves the route group is not merely hidden.
- **The fourth-plan proof**: a plan that is not a subset of any other, granting
  `trip.collaborators` without `ai.command`, added by editing one file and
  shipped disabled. This is the proof the split architecture is real rather
  than asserted — do not skip it because nothing ships it.

Closes: the admin-surface box; the referral boxes; the non-admin box; the
fourth-plan box. *(The trial box is Phase 2's — see the correction there.)*

## M21 — four phases, after M20's gate closes

Not open. Sketched here so M20 does not build into it by accident.

1. **The subscription table and the priced versions** (links 1, 2). Migration:
   `subscriptions` + `users.stripe_customer_id`. `price_minor`, `currency`,
   `stripe_price_id` onto the plan-version entries. The consistency check —
   *every published priced version's `stripe_price_id` resolves to a Stripe
   Price with the same amount and currency* — because a divergence errors
   nowhere and means the pricing page and the card statement disagree.
2. **Checkout and the webhook** (links 3, 4). Hosted checkout; **no card number
   anywhere in this repo's DOM**. The webhook is the sole writer of
   subscription state, with signature verification, idempotency and
   out-of-order tolerance each a gate box. A redirect is a hint, never a grant.
3. **The billing surface and failed payment** (links 5, 6). A Plan section at
   the **top of the existing account sheet**, not a route: plan/version/state,
   two meters against the pinned version's per-user ceilings, past-due copy
   that names the loss before it happens, a referral row, an inline three-plan
   chooser. Cancelling lapses through **M20's resolver** — no second downgrade
   path. **Grace window: 3 days from the decline** — shorter than Stripe's own
   retry schedule, so an account lapses while Stripe is still retrying and a
   later successful retry restores it through the ordinary webhook path. One
   constant, three readers.
4. **The revenue half of the unit economics** (link 7). MRR, ARPU twice and
   labelled, trailing-30-day margin, and the underwater list **segmented by
   grant source** — a comped account is underwater by construction and will
   swamp the list unsegmented.

**The standing constraint across all four:** if M21's diff touches
`modelSelection.ts`, `quota.ts` or `members.ts`, the split has failed. Check it,
do not assume it — it is a gate box.

1. **The grace window is 3 days** from the decline — M21 link 6.
2. **The trial is one time ever per account** — and it **moved milestones**:

3. **`ai-live` is on in production before release, and the flag stays** as the
   emergency disable. This one is **not a Phase 3 build decision after all** —
   it is a deployment step at release plus an ADR amendment, both now written.
   What Phase 3 owes it is the ordering constraint below.

**What Phase 3 must not do:** flip the fallthrough. The flip belongs at
release, *after* the entitlement gate is live in production. Phase 3 builds the
gate; someone else throws the switch, and ADR-019's amendment says in what
order and with what command.

## What must not happen

- **A price string in M20's diff.** Contracts, plan file, tests, fixtures,
  seeds — anywhere. M21 link 2 adds them.
- **A comparison operator near a plan.** `plan >= "paid"` in any form. The
  ladder is presentation; `can(ent, capability)` is the only question.
- **An entitlement claim in the JWT**, or a resolution in the Edge proxy. A
  downgrade must bite before a token refreshes.
- **Entitlements importing a trip type.** Phase 4 is where this dies.
- **A dispatched M20 migration behind an unapplied `0018`.** See preflight.
- **A cleanup job over `entitlement_grants`.** Deleting expired rows hands a
  second trial to everyone who ever had one, and it looks like generosity
  rather than a bug.
- **Flipping `ai-live`'s production fallthrough to Live before the entitlement
  gate is live there.** That interval has no spend control at all — the exact
  condition ADR-019 was written for.
- **Turning live AI on with a widening rule instead of the fallthrough**, or
  leaving pre-release targeting rules in place at the flip. Either makes a rule
  load-bearing, and the emergency disable stops being one action.
- **"Tidying" `defaultValue: false` in the flag declaration** to match the
  dashboard. It is the code's fail-closed fallback for an unreachable Flags
  service; the two point opposite ways deliberately.
- **`test:e2e` standing in for `test:e2e:ci-like`** in any verdict, PR checkbox
  or claim made to Mitchell.
