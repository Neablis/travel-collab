# The SEO Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. One worktree per part; each PR opens as a **draft**.

**Goal:** Make the public playbook library crawlable and indexable: a robots file, a sitemap, canonical URLs, server-rendered day pages with real 404s and slugged URLs, structured data, and city and country pages.

**Architecture:** Five stacked PRs. Parts 1-2 are crawl plumbing that needs no page to change how it renders. Part 3 opens a second hole in the lint wall so `/playbooks/**/page.tsx` reads `src/server` in-process and hands the result to the existing client screens as initial data. Parts 4-5 build on those server reads.

**Tech Stack:** Next.js 16 App Router (`robots.ts`, `sitemap.ts`, `generateMetadata`, `notFound`, `permanentRedirect`), Drizzle over Postgres, Vitest, Playwright.

**Spec:** `docs/specs/2026-10-02-seo-pass-design.md`. Read it with this plan; section numbers below (§) refer to it.

## Global Constraints

- **Private equals missing.** A private, moderated, deleted or nonexistent day gives the same 404 with the same body. Nothing distinguishes them in the page, the sitemap or a redirect. A redirect is issued only *after* the read has succeeded.
- **An author is named the way the library names them, and no other way.** Since PR #294 (ADR-061 decision 4, amended 2026-10-02) that is `publicNameFor`: "Dana R.", or the handle when there is no usable name. Titles, descriptions and structured data take the name the server already resolved (`publicAuthor(...).displayName`, `DiscoverDay.ownerDisplayName`, `publicNamesOf`). Never derive one from `ownerId` in a page or component, and never print an address. This supersedes the spec's §3 "pseudonymous" line, which was written before #294 merged.
- **Token routes stay out of every index.** `/s/**` and `/invite/**` get `noindex` metadata and are **not** listed in `robots.txt`.
- **No contract change and no migration.** Slugs are derived, never stored. Needing either is a design change: stop and go back to Mitchell.
- **No new `/api/v1/**` endpoint.** A new internal route gets one line in `apps/web/src/server/public-api/exposure.ts`.
- **Every new export carries a one-line JSDoc** (`scripts/check-docstring-wall.mjs`, `docs/guidelines/commenting.md`).
- **An e2e verdict comes only from `pnpm --filter web test:e2e:ci-like`.** Every test is seen to fail before it counts (CLAUDE.md rules 1 and 3).
- **Mid-branch verification is the `minimal-check-subset` skill's output.** `pnpm check` runs once, on the top part, before part 1 merges (Task 5.5).
- Node 24 (`nvm use`), not 26. All `pnpm --filter web …` commands run from the repo root.

The four items of §8:

1. **Wall globs and fixtures.** Each exemption is its own flat-config block placed after the admin block in `apps/web/eslint.config.mjs`, restating the two restrictions it keeps (`@tc/domain`, `@/lib/authConfig`). This is the admin block's mechanism: ESLint replaces a rule's options for the last matching block, so an `ignores` entry alone would be undone by the authConfig block. Globs: `["src/app/sitemap.ts", "src/app/robots.ts"]` (Part 2) and `["src/app/(app)/playbooks/**/page.tsx"]` (Part 3). Fixtures are listed in Tasks 2.2 and 3.2. `lintFixture` gains a `file` option, because its `__name__` naming cannot produce a file called `sitemap.ts` or `page.tsx`.
2. **How `/` avoids crossing the session boundary.** The proxy already runs on every request for `/`. A signed-out request is rewritten to `/welcome` and the rewrite response carries `Cache-Control: private, no-store` and `Vary: Cookie`. A signed-in request passes through to the app home as today. The e2e script proves three things: the header is present, a signed-in request never gets the landing, and a browser that saw the landing and then signed in gets the app home at `/`. If the header assertion fails because Next overrides it for the prerendered `/welcome`, the fallback is `export const dynamic = "force-dynamic"` on `(front)/welcome/page.tsx`; report it in the PR body if used.
3. **Counts** (Neon project `caesura`, branch `production`, read 2026-10-02): **155** published days, **318** distinct cities, **33** distinct countries. 293 of the 318 cities have exactly one day; 6 have three or more. So: **no sitemap chunking** (155 against a 50,000 limit), and **thin place pages need a threshold**. A city or country page exists for any place with a published day (the spec's rule), but it is indexable and in the sitemap only at `MIN_INDEXED_PLACE_DAYS = 3`; below that it is `noindex, follow`. The threshold is one constant in `lib/playbookUrls.ts`.
4. **One Discover implementation.** A new `discoverFor(input, readerId)` in `server/playbooks.ts` holds the "a signed-out reader reads Everyone" rule and calls `discoverDays`. The `/api/playbooks` handler and the page both call it. The day read gets the same treatment: `sharedDayView` in `server/sharedDayView.ts`, called by `/api/saved-days/[savedDayId]` and by the page.

Two sequencing notes, neither a design change:

- **The day `<title>` gains its city in Part 3, not Part 1.** Part 1's title comes from the `meta` route, whose `LinkPreviewMeta` contract carries only a title and a description. Adding the city there is a contract change. Part 1 ships the day's name; Part 3 reads in-process and ships name and first city.
- **The breadcrumb's city crumb arrives in Part 5**, with the city page it links to. Part 4 emits Playbooks → day.

/** Robots metadata for a page that must stay out of every index and pass no links. */
export const NOINDEX = { index: false, follow: false } as const;

/** Robots metadata for a page that stays out of the index but whose links are followed. */
export const NOINDEX_FOLLOW = { index: false, follow: true } as const;

/**

```ts
export function pageMetadata({
  title,
  description,
  image,
  canonical,
  robots,
}: {
  // A plain string composes with the layout's `%s — Caesura` template; pass
  // `{ absolute }` for a page that owns its whole <title>.
  title: string | { absolute: string };
  description: string;
  // A card drawn for this one link (spec 2026-09-27 §2.2, `/api/og/**`). It
  // goes FIRST, and the site card stays after it as the fallback for an
  // unfurler that cannot fetch the first.
  image?: { url: string; alt: string };
  // The path a search engine should index this page under, relative to
  // `metadataBase`. Also og:url, so a shared link and the index agree.
  canonical?: string;
  robots?: Metadata["robots"];
}): Metadata {
  const ogTitle = typeof title === "string" ? title : title.absolute;
  return {
    title,
    description,
    ...(canonical === undefined ? {} : { alternates: { canonical } }),
    ...(robots === undefined ? {} : { robots }),
    openGraph: {
      siteName: SITE_NAME,
      type: "website",
      locale: "en_US",
      // og:title stays suffix-free — og:site_name already carries the brand,
      // and share cards render both.
      title: ogTitle,
      description,
      ...(canonical === undefined ? {} : { url: canonical }),
      images: image === undefined ? [OG_IMAGE] : [{ ...image, width: 1200, height: 630 }, OG_IMAGE],
    },
    // Stated rather than left to Next's inheritance from openGraph, so a
    // framework change cannot alter what a card shows.
    twitter: { card: "summary_large_image", title: ogTitle, description },
  };
}
```

In `layout.tsx`, import `siteRobots` beside `SITE_DESCRIPTION` and add one key to `metadata`:

// apps/web/src/app/robots.ts
import type { MetadataRoute } from "next";
import { deploymentOrigin } from "@/lib/deploymentOrigin";

// The same on every deployment. A preview is kept out of the index by the root
// layout's `noindex` (`siteRobots`), which a disallow here would hide: a
// disallowed URL is never fetched, so its robots meta is never read. For the
// same reason `/s/` and `/invite/` are NOT listed — they carry `noindex`, and
// naming the prefixes would advertise them.
/** `/robots.txt`: everything allowed except `/api/`, and where the sitemap is. */
export default function robots(): MetadataRoute.Robots {
  return {
    rules: { userAgent: "*", allow: "/", disallow: "/api/" },
    sitemap: `${deploymentOrigin()}/sitemap.xml`,
  };
}
```

import { expect, test, type Browser, type Page } from "@playwright/test";

// The SEO pass's one script (spec 2026-10-02-seo-pass §6). What a crawler
// receives is the server's HTML, so most of this reads responses rather than
// driving a page.

/** A browser context with no session at all. */
async function stranger(browser: Browser): Promise<Page> {
  const context = await browser.newContext({ storageState: { cookies: [], origins: [] } });
  return context.newPage();
}

const HEADLINE = "Put the best day on repeat.";

test("a signed-out / serves the landing in place, uncached, with one h1", async ({ browser }) => {
  const visitor = await stranger(browser);
  const response = await visitor.request.get("/", { maxRedirects: 0 });
  expect(response.status()).toBe(200);
  expect(response.headers()["cache-control"]).toContain("no-store");
  const html = await response.text();
  expect(html).toContain(HEADLINE);
  expect(html.match(/<h1[\s>]/g) ?? []).toHaveLength(1);
  expect(html).toMatch(/<link rel="canonical" href="[^"]*\/"\s*\/?>/);
  await visitor.context().close();
});

test("a signed-in / is the app home, never the landing", async ({ page }) => {
  const html = await (await page.request.get("/", { maxRedirects: 0 })).text();
  expect(html).not.toContain(HEADLINE);
  await page.goto("/");
  await expect(page.getByRole("heading", { name: "Your trips" })).toBeVisible();
});

test("robots.txt allows the site, keeps /api out, and names the sitemap", async ({ browser }) => {
  const visitor = await stranger(browser);
  const body = await (await visitor.request.get("/robots.txt")).text();
  expect(body).toContain("Disallow: /api/");
  expect(body).toMatch(/Sitemap: \S+\/sitemap\.xml/);
  expect(body).not.toContain("/invite");
  expect(body).not.toContain("/s/");
  await visitor.context().close();
});

/**
 * Every day a stranger can open, for `sitemap.ts`: published, not moderated,
 * not deleted. Its own query, and not `discoverDays`: that one answers a

 * would silently drop the rest of the library.

// apps/web/src/lib/playbookUrls.ts

// The public library's URLs, built and read in one place (SEO pass, D7). Pure,
// so the server pages, the client link builders and the sitemap share it.
//
// A day's URL is `/playbooks/day/<slug>-<uuid>`. The slug is DERIVED from the
// day's name on every build and stored nowhere; the uuid alone resolves the
// day. A link whose slug is missing or stale still opens: the page redirects
// it to the current URL.

const MAX_SLUG_LENGTH = 60;
const UUID_AT_END = /(?:^|-)([0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})$/i;

/** Lowercase ASCII words joined by hyphens, at most 60 characters; empty when the text has none. */
export function slugify(text: string): string {
  return text
    .normalize("NFKD")
    .replace(/[̀-ͯ]/g, "")
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, "-")
    .replace(/^-+|-+$/g, "")
    .slice(0, MAX_SLUG_LENGTH)
    .replace(/-+$/, "");
}

/** A day's route segment: `<slug>-<uuid>`, or the bare uuid when its name has no slug. */
export function daySegment(day: { savedDayId: string; name: string }): string {
  const slug = slugify(day.name);
  return slug === "" ? day.savedDayId : `${slug}-${day.savedDayId}`;
}

/** A day's canonical path, `/playbooks/day/<slug>-<uuid>`. */
export function dayPath(day: { savedDayId: string; name: string }): string {
  return `/playbooks/day/${daySegment(day)}`;
}

/** The uuid at the end of a day segment (lowercased), or null; and whatever slug came before it. */
export function parseDaySegment(segment: string): { id: string | null; slug: string } {
  const match = UUID_AT_END.exec(segment);
  if (match === null) return { id: null, slug: "" };
  const id = match[1]!.toLowerCase();
  return { id, slug: segment.slice(0, segment.length - id.length).replace(/-$/, "") };
}
```

import { publicAuthor } from "./playbooks";

import { moderationOf, publishedAtOf, readableSavedDay } from "./savedDays";

/**

export async function sharedDayView(savedDayId: string, readerId: string | null): Promise<SharedDayView | null> {

    day,
    isAuthor,
    author,
    pinning: readerId === null ? false : schedulePinBackfill(day, readerId),
    publishedAt,
    moderation,
  };
}

// apps/web/src/lib/jsonLd.ts
import { SITE_DESCRIPTION, SITE_NAME } from "./siteMetadata";

// Structured data for the pages a search engine indexes (SEO pass, Part 4).
// Pure builders; the server component serialises the result into a
// `<script type="application/ld+json">`. Kept small on purpose: Google has no
// rich result for an itinerary, and the breadcrumb is the part likely to show.

const CONTEXT = "https://schema.org";

/** One JSON-LD object. */
export type JsonLdNode = Record<string, unknown>;

/** What a day's structured data is built from. Every string is one the page already shows. */
export type DayJsonLdInput = {
  origin: string;
  /** The day's canonical path. */
  path: string;
  name: string;
  description: string;
  /** The author's public name as the server resolved it (`publicAuthor().displayName`). */
  author: string;
  /** Stop titles, in order. */
  stops: readonly string[];
  rating: number | null;
  reviewCount: number;
  /** The breadcrumb's middle crumb, when the day's first city has a page. */
  city?: { name: string; path: string };
};

/** The landing's `Organization`. */
export function organizationJsonLd(origin: string): JsonLdNode {
  return { "@context": CONTEXT, "@type": "Organization", name: SITE_NAME, url: origin, logo: `${origin}/icon.svg` };
}

/** The landing's `WebSite`. */
export function webSiteJsonLd(origin: string): JsonLdNode {
  return { "@context": CONTEXT, "@type": "WebSite", name: SITE_NAME, url: origin, description: SITE_DESCRIPTION };
}

/**
 * A shared day as a `TouristTrip` whose itinerary lists its stops, and the
 * `BreadcrumbList` above it.
 *
 * The author is `provider`: schema.org's `Trip` has no `author`. The rating is
 * left out entirely until somebody has reviewed the day, so a search engine is
 * never told "0 stars".
 */
export function dayJsonLd(input: DayJsonLdInput): JsonLdNode[] {
  const url = `${input.origin}${input.path}`;
  const trip: JsonLdNode = {
    "@context": CONTEXT,
    "@type": "TouristTrip",
    name: input.name,
    description: input.description,
    url,
    provider: { "@type": "Person", name: input.author },
    itinerary: {
      "@type": "ItemList",
      itemListElement: input.stops.map((name, i) => ({
        "@type": "ListItem",
        position: i + 1,
        item: { "@type": "TouristAttraction", name },
      })),
    },
    ...(input.reviewCount > 0 && input.rating !== null
      ? {
          aggregateRating: {
            "@type": "AggregateRating",
            ratingValue: input.rating,
            reviewCount: input.reviewCount,
            bestRating: 5,
            worstRating: 1,
          },
        }
      : {}),
  };
  const crumbs = [
    { name: "Playbooks", path: "/playbooks" },
    ...(input.city === undefined ? [] : [input.city]),
    { name: input.name, path: input.path },
  ];
  const breadcrumb: JsonLdNode = {
    "@context": CONTEXT,
    "@type": "BreadcrumbList",
    itemListElement: crumbs.map((crumb, i) => ({
      "@type": "ListItem",
      position: i + 1,
      name: crumb.name,
      item: `${input.origin}${crumb.path}`,
    })),
  };
  return [trip, breadcrumb];
}

/** JSON for a `<script>` body: `<` is escaped, so a day named `</script>` cannot end the element. */
export function serializeJsonLd(data: JsonLdNode | JsonLdNode[]): string {
  return JSON.stringify(data).replace(/</g, "\\u003c");
}

/**
 * How many published days a city or country page needs before it is indexed
 * and listed in the sitemap. Below it the page still opens and is
 * `noindex, follow`. Production on 2026-10-02: 318 cities over 155 days, 293 of
 * them with one day — a one-day list is a thin page that duplicates its day.
 */
export const MIN_INDEXED_PLACE_DAYS = 3;

/** Days per city or country page. Discover's own page size. */
export const PLACE_PAGE_SIZE = 24;

/** `/playbooks/city/<slug>`, or null for a city whose name has no slug (link to Discover's `?city=` instead). */
export function cityPath(city: string): string | null {
  const slug = slugify(city);
  return slug === "" ? null : `/playbooks/city/${slug}`;
}

/** `/playbooks/country/<slug>` from an ISO alpha-2 code, slugged from its English name; null when it has none. */
export function countryPath(code: string): string | null {
  const name = countryName(code);
  // `countryName` hands an unmappable code back unchanged; that is not a name.
  const slug = name === null || name === code ? "" : slugify(name);
  return slug === "" ? null : `/playbooks/country/${slug}`;
}

/** A place page's URL for page `page`; page one is the bare path, so it is self-canonical. */
export function placePagePath(path: string, page: number): string {
  return page <= 1 ? path : `${path}?page=${page}`;
}

 * Every place a published day touches, as the pages that list them.
 *
 * `cities` is free text, so spellings that slug alike ("São Paulo", "Sao
 * Paulo") are one page, named by the spelling most days use. Countries are ISO
 * codes and slug by their English name. A value with no slug has no page.
 *
 * `days` for a merged city is the sum over its spellings, which counts a day
 * twice only if it carries two spellings of one city — a day list is the
 * exact number, and `publishedDaysPage`'s `total` is what the page prints.
 */
export async function publishedPlaces(): Promise<PlacePage[]> {
  const [cityRows, countryRows] = await Promise.all([
    db.execute<{ value: string; days: number }>(sql`
      select city as value, count(*)::int as days
      from saved_days d, unnest(d.cities) as city
      where d.visibility = ${SavedDayVisibility.enum.public} ${notDeleted} ${notModerated}
      group by city
      order by days desc, city asc
    `),
    db.execute<{ value: string; days: number }>(sql`
      select country as value, count(*)::int as days
      from saved_days d, unnest(d.countries) as country
      where d.visibility = ${SavedDayVisibility.enum.public} ${notDeleted} ${notModerated}
      group by country
      order by days desc, country asc
    `),
  ]);

  const bySlug = new Map<string, PlacePage>();
  for (const row of cityRows.rows) {
    const value = String(row.value);
    const slug = slugify(value);
    if (slug === "") continue;
    const key = `city:${slug}`;
    const page = bySlug.get(key);
    // Rows arrive most-used first, so the first spelling seen names the page.
    if (page === undefined) bySlug.set(key, { kind: "city", slug, name: value, cities: [value], countries: [], days: Number(row.days) });
    else {
      page.cities.push(value);
      page.days += Number(row.days);
    }
  }
  for (const row of countryRows.rows) {
    const code = String(row.value);
    const name = countryName(code);
    const slug = name === null || name === code ? "" : slugify(name);
    if (slug === "") continue;
    bySlug.set(`country:${slug}`, { kind: "country", slug, name: name!, cities: [], countries: [code], days: Number(row.days) });
  }
  return [...bySlug.values()];
}

/** The page for one slug, or null when no published day touches it — which the route answers with a 404. */
export async function placeFor(kind: "city" | "country", slug: string): Promise<PlacePage | null> {
  return (await publishedPlaces()).find((place) => place.kind === kind && place.slug === slug) ?? null;
}

/**
 * Published days for a place or an author, most-added first, one offset page.
 *
 * `matchPredicate` with a reader who owns nothing and `publishedOnly`, so the
 * rows are exactly what a stranger can open, and `toDiscoverDay`, so each is
 * the card Discover would show. Offset paging, unlike `discoverPage`'s keyset:
 * a place page is addressed by `?page=N`, which a crawler follows as a link.
 */
export async function publishedDaysPage(
  filter: { cities?: string[]; countries?: string[]; authorId?: string },
  page: { limit: number; offset: number },
): Promise<{ days: DiscoverDay[]; total: number }> {
  const query: DiscoverQuery = {
    cities: filter.cities ?? [],
    countries: filter.countries ?? [],
    authorId: filter.authorId ?? null,
    scope: "everyone",
    sort: "most-added",
    budget: "any",
    length: "any",
    publishedOnly: true,
    readerId: null,
  };
  const rows = await db.execute<DiscoverRow>(sql`
    select ${discoverColumns}, ${matchedCount(query)}::int as matched_count,
      count(*) over ()::int as total_count
    from saved_days d
    where ${matchPredicate(query)}
    order by ${orderBy(query.sort)}
    limit ${page.limit} offset ${page.offset}
  `);
  return {
    days: [...rows.rows]
      .map((row) => toDiscoverDay(row, query.cities, null))
      .filter((day): day is DiscoverDay => day !== null),
    total: Number(rows.rows[0]?.total_count ?? 0),
  };
}

`total` is 0 for a page past the end. The route treats an empty page other than page one as a 404.
