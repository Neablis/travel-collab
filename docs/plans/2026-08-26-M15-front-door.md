# M15 Front Door — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Caesura the unauthenticated surface it has never had — a landing page at `/welcome`, and custom sign-in and sign-up screens replacing NextAuth's default page — and close M15.

**Architecture:** Two Next.js route groups split the app shell from the front door. `app/(app)/` keeps `AppHeader` in its own layout and holds every authenticated route (`/`, `/playbooks`, `/trips/**`); `app/(front)/` holds `/welcome`, `/signin` and `/signup` with no app chrome. `/` redirects unauthenticated visitors to `/welcome`. All three front-door screens are ordinary client UI — **the lint wall forbids `src/app/**` from importing `@/server/*`**, so nothing here calls `auth()`; sign-in is dispatched through `next-auth/react`'s `signIn`, the same seam `AccountMenu.tsx` already uses for `signOut`.

**Tech Stack:** Next.js 15 App Router, React 19, NextAuth v5 beta (`next-auth@^5.0.0-beta.32`), Tailwind v4, Vitest + Testing Library, Playwright.

**Spec:** `docs/milestones/M15-front-door.md` (scope + exit gate) and the design source of truth `.design-sync/handoff/design/Trip Planner Redesign.dc.html` — `isLanding` ≈1469-1541, `isAuth` ≈1543-1582, copy bindings ≈3388-3396. Companion: `.design-sync/handoff/SPEC.md`.

## Decisions taken before this plan (Mitchell, 2026-08-26)

These resolve M15's two open questions and amend three gate lines. **Task 5 records them in `docs/milestones/M15-front-door.md`.** Do not re-litigate them mid-build.

2. **The landing copy ships verbatim, as aspiration.** The hero's "Save the highlights when you get back, share them with the world, and let other travelers remix the best parts into their own adventures" sells M11 (fork/remix) and M12 (community), neither of which exists. This is the explicit approval M15's gate item asks for. **Do not soften, trim or reword it.** The proof chip "Remix anyone's itinerary" ships for the same reason.
3. **There is no first-run screen.** The design's one-field "What are you planning, Sam?" screen is dropped; the merged four-step `NewTripWizard` is the only create path. This is safe because the gate's real requirement — *create a first trip from a name alone* — is **already satisfied**: `NewTripWizard.tsx:431` renders a "Create empty" button on every step, gated only by `trimmedName !== ""` (`:215`). Task 4 proves it with a test.
4. **A signed-in user with no trips sees Home's empty state**, not a separate screen. "Brand new account" is inferred from zero trips; there is no user table to record it in. Someone who deletes every trip sees the empty state again, which is correct behavior, not a bug.
5. **The landing lives at `/welcome`; `/` redirects to it** when unauthenticated. This amends the gate line "an unauthenticated visitor to `/` sees the landing page."
6. **The account menu is already done.** `components/AccountMenu.tsx` (Phase 8b) ships name, email and a real `signOut({ callbackUrl: "/" })`. No account model exists, so "Your account" gets nothing. Task 5 records the scope item as satisfied.

## Global Constraints

Every task's requirements implicitly include this section.

- **The lint wall (`apps/web/eslint.config.mjs:26-27`).** `src/**/*.{ts,tsx}` may not import `@tc/domain` or `@/server/*`. Only `src/server/**`, `src/app/api/**` and `src/app/.well-known/**/route.ts` are exempt. **`src/app/page.tsx`, `src/app/layout.tsx` and every file this plan creates are bound by it.** Never add an exemption to get around this — AGENTS.md: a blocking invariant is a finding to report to Mitchell, not a rule to bend.
- **The element wall (`apps/web/eslint.config.mjs:51-72`).** No raw `<button>`, `<input>`, `<textarea>`, `<select>`, `<label>`, `<h1>`-`<h6>` or `<table>`, and no `style` attributes. Render through `src/components/ui/*`. The design source is raw HTML with inline styles throughout — **translate it to primitives, never copy its markup**. Enumerated exceptions need a line-level `eslint-disable` with a reason.
- **The color wall (`scripts/check-color-wall.mjs`, run by `pnpm lint`).** Tokens only — no raw hex or arbitrary colors.
- **No new contract fields, no new commands, no new domain rules.** `CreateTrip` carries only a name and that does not change (`SPEC.md` D4). No UI module may import `@tc/domain`.
- **Do not invent product copy.** Landing and auth copy is transcribed verbatim from the design file, at the line numbers each task cites. Error-state copy is the one exception — the design draws only the happy path, so those strings are ours to author (M15 scope item 5).
- **Every `<Preview>` needs a `preview-registry.ts` entry** with its real milestone, or the sync test fails.
- **The e2e suite must stay green after every task.** All 24 specs run pre-authenticated through `e2e/auth.setup.ts` → `signInAsDevUser` (`e2e/helpers.ts:68-81`), which drives `page.goto("/")` → click link named `"Sign in"` → fill `input[name="username"]` → click a button matching `/sign in with dev login/i`. **Task 1 preserves all four of those selectors on the new screens so `helpers.ts` needs zero changes.** Breaking them breaks every spec at once.
- Commands: `pnpm check` = `pnpm typecheck && pnpm lint && pnpm test`. Unit tests: `pnpm --filter web test`. Integration: `pnpm --filter web test:int`. E2E: `pnpm --filter web test:e2e`.
- **Primitive APIs, verified against the source while writing this plan** — use these, do not extend them: `Heading{level: 1|2|3|4}`; `Text{variant?: "body"|"secondary"|"muted", as?: "p"|"span"}` (defaults `body`/`p`); `DataText{size?: "xs"|"sm"|"base", as?: "span"|"time"}` (defaults `sm`/`span`); `Badge{variant: "neutral"|"danger"|"warning"|"success"|"info"|"brand"}`; `Banner{variant: "warning"|"info"|"danger"|"success", actions?}`; `Card{raised?, as?: "div"|"li"}`; `Button{variant: "primary"|"secondary"|"ghost", size}` plus `buttonVariants` for links; `FormField{id, label, description?, hint?, error?}`; `EmptyState{icon?, title, body?, action?}`; `Preview{id, size: "compact"|"container", note?, className?}`.

export function AuthScreen({
  mode,
  devLoginEnabled,
}: {
  mode: "signin" | "signup";
  devLoginEnabled: boolean;
}) {
  const [username, setUsername] = useState("");

  return (
    <div className="flex min-h-screen flex-col bg-paper text-ink">

            <Button
              type="button"
              variant="secondary"
              className="w-full"
              onClick={() => void signIn("google", { callbackUrl: "/" })}
            >
              Continue with Google
            </Button>

            {devLoginEnabled && (
              <form
                className="flex flex-col gap-2"
                onSubmit={(event) => {
                  event.preventDefault();
                  void signIn("dev-login", { username, callbackUrl: "/" });
                }}
              >
                <FormField id="dev-login-username" label="Username">
                  <Input
                    id="dev-login-username"
                    name="username"
                    value={username}
                    onChange={(event) => setUsername(event.target.value)}
                  />
                </FormField>
                <Button type="submit" variant="ghost">
                  Sign in with dev login
                </Button>
              </form>
            )}

            <Link href={mode === "signup" ? "/signin" : "/signup"} className="text-sm font-semibold text-brand">
              {mode === "signup" ? "Sign in" : "Create an account"}
            </Link>
          </Card>
        </div>
      </main>
    </div>
  );
}
