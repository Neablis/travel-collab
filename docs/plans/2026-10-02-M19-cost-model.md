## Part 1 — a price is per person

1. **`packages/contracts/src/costs.ts`** (new, exported from the index):
   - `stopHeadcount(activity: { participants: readonly string[] }, memberCount: number): number`
     returns `participants.length`, or `max(memberCount, 1)` when that is 0.
   - `stopTotal(activity, memberCount): number` returns minor units, or `0` when the stop has
     no cost.
   - `isCommittedCost(kind: ActivityKind): boolean` returns `kind !== "pending"`.
   - Unit tests cover the empty-participants case, a solo trip and a pending stop. Each one is
     seen to fail.
2. **Domain:** `rollupCosts(state, memberCount)` sums `stopTotal`. `projectTripDetail` passes
   `state.members.length`, which is the log's own members, so rebuild equals stored. Export a
   pure `recostDetail(detail, memberCount): TripDetail` that recomputes
   `days[].costSubtotal`, `unscheduledCostSubtotal`, `tripCostTotal` and `budgetRemaining`
   from `detail.activities`.
3. **Server overlay:** wherever `trip-access.ts` overlays `effectiveMembers` onto a
   `TripDetail`, also apply `recostDetail(detail, members.length)`. Integration test: a trip
   with one priced stop and nobody picked; grant a second member; the read total doubles, and
   no event was appended.
4. **Web readers:** `apps/web/src/lib/cost.ts` (`tripSpend`, `plannedOfBudgetLine`,
   `daySpend`) and the board's totals read the overlaid fields, or call `stopTotal` with
   `detail.members.length`. No raw `cost.amountMinor` sum is left in a trip-total path.
   `grep -rn "cost?.amountMinor\|cost.amountMinor"` over `apps/web/src` and `packages/pages/src`
   is the audit; list each remaining hit with why it is a per-person read.
5. **`@tc/pages` widgets:** `cost`, `cost.rows`, `cost.breakdown` and `cost.chart` sum
   `stopTotal`. Each widget's resolution context needs the member count; add it where the trip
   detail enters the resolver, and do not add a second way to read members.
6. **Committed vs estimate:** the Settings sheet's budget line and the `cost` widget show the
   committed amount and the estimate part ("¥… committed · ¥… estimated") using
   `isCommittedCost`. The wording follows the existing copy style.
7. **Editor:** `ActivityEditor`'s Cost input is labelled *per person*. Under it, when there is
   a cost, a muted line reads *"× 3 people = ¥9,000"*. Viewers see the same line in the
   read-only sheet.
8. **Assistant:** `server/ai/writeTools.ts` (and any tool description that mentions `cost`)
   says the cost is per person.
9. **Contracts protocol:** a `docs/contracts/CHANGELOG.md` entry for the meaning change. Add
   `.describe("Price for one person …")` on `cost`, regenerate `openapi.json`, and make the
   drift test pass. Update `docs/guidelines/using-the-api.md` if it describes cost.
10. **Fixtures:** `pnpm seed:verify` stays green. If the Japan expectations pin totals, update
    the pin with a comment that cites ADR-060.

Verification for part 1: run the `minimal-check-subset` output for the touched packages,
plus `pnpm --filter web test:int` for the overlay test. Every new test is seen red first
(CLAUDE.md rule 3).

## Part 2 — who owes what

- `packages/contracts/src/costs.ts`: `balances(activities, memberIds)` returns
  `{ perMember: { userId, share, paid, net }[], unpaid }`, following ADR-060 decision 6.
  It is pure and property-tested: the nets sum to `-unpaid`.
- `@tc/pages` primitives: `cost.balances` ("Who owes what") and `person.share` ("What one
  person is in for", the parked `w-person`). Member names come through the existing profile
  join.
- Add `cost.balances` to the Money template in `templates.ts`. This affects new trips only.
