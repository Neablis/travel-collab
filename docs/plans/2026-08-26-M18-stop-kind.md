# M18 — `kind` and `tags` on the activity contract: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give an activity two real fields — `kind` (a booking/travel workflow
state) and `tags` (what sort of thing the stop is) — set by command, carried
through the event store, and visible in the projection, so the Calendar, the
home hero and the stop card stop reading a kind out of note prose.

**Architecture:** Both fields are **additive changes to the existing V1 event
payloads**, using Zod `.default()` — exactly the pattern M3 used for `anchors`
and M4 used for `cost`. There is no `V2` event, no event-store migration, and
no rewrite of stored events: previously-stored `ActivityAdded`/`ActivityUpdated`
payloads replay as `kind: "planned"`, `tags: []`. `kind` is non-nullable with a
`"planned"` default; `tags` follows the `anchors` precedent (omitted =
unchanged, whole-array replace, never null).

**Tech Stack:** TypeScript, Zod (contracts), pure reducers (`@tc/domain`),
Vitest, Next.js + MSW (`apps/web`), pnpm workspaces.

**Spec:** `docs/milestones/M18-stop-kind.md` (scope + exit gate); `docs/known-issues.md`
KI-47 (the `tags` half); `.design-sync/handoff/design/Trip Planner Redesign.dc.html`
(the tag vocabulary and each tag's "power").

- [ ] **Step 3: Add the two enums to `packages/contracts/src/activity.ts`**

Insert immediately after the `Location` schema (after the `.refine(...)` block

```ts
// Where a stop sits in the booking/travel workflow. Exactly one per activity,
// and never absent: "planned" is the zero value, which is why the field
// defaults rather than being nullable — db-seed.ts and the design handoff's
// export (`enums.stopStatus`) both already treat it that way. Calendar reads
// `transit` to split a travel day; `N to book` counts everything that is
// neither `booked` nor `transit` (M18).
export const ActivityKind = z.enum(["booked", "hold", "idea", "transit", "planned"]);
export type ActivityKind = z.infer<typeof ActivityKind>;

// What sort of thing a stop IS — orthogonal to where it is in the workflow.
// A closed vocabulary, never freeform: the design attaches behaviour to each
// tag ("power"), and a free string can't carry one.
//
// The handoff lists six; `considering` and `travel` are deliberately absent
// because ActivityKind already answers those (`idea` and `transit`). Two
// fields that can disagree about one fact is a bug generator: a stop tagged
// `considering` while its kind says `booked` would render dashed under a
// "Booked" badge with its cost outside the committed total, and no surface
// would own the contradiction. See docs/milestones/M18-stop-kind.md.
export const ActivityTag = z.enum(["meal", "lodging", "ticketed", "outdoors"]);
export type ActivityTag = z.infer<typeof ActivityTag>;
```

    version: 1,

function apply(state: TripState, command: Parameters<typeof decideTripCommand>[1]): TripState {

  if (!d.ok) throw new Error(`expected ok, got rejection: ${d.rejection.code}`);
  return d.events.reduce(evolveTrip, state);
